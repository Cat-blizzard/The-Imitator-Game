**运动参考接口已实际跑通一个开发样本，但跨机制收益尚未得到验证。** 四个冻结新布局全部通过原生仿真验收，随后四次首图审核均因返回字段不符合 schema 而结束，原定八条 A/B 视频没有提交。没有替换失败样本、重新审核这四张图或把 unknown 计为通过。

## 1. 试验问题与对照

研究问题：完整的仿真过程参考，能否帮助视频模型保持不同任务的必要动作，而不仅依靠首图及文字猜测过程？

- A：人物首图作为 `first_frame`，加现有任务文字。
- B：同一人物图作为 `reference_image`，加完整仿真 `reference_video` 和相同任务文字；只附加统一的媒介角色说明。
- 模型：首图 `gemini-nano-banana-2.1`；视频 `doubao-seedance-2-5-260628`；审核 `gemini-3.1-pro-preview`。服务配置和原审核谓词均冻结。
- 原生轨迹完整区间统一缩放到 12 秒、24 fps、720×720；原始状态与视频不改。要求保持对象、必要事件、持握和解剖手侧，不要求人类复制机器人关节角及停顿。
- **混杂因素**：B 同时改变图片输入角色并增加视频，最多估计整个条件组合的效果，不能单独归因于运动视频。
- 开发资格样本为已有钩取任务，不进入四个新布局分母。新布局相对于本轮运动条件调试保留，但四种机制的控制技能均已开发过，不是未见机制。

原先假设“接口可用后可以直接批量对照”被实际首图审核故障推翻。另一个假设“没有给足任务语义才会失败”也不足以解释本轮：这里首先失败的是审核输出协议，尚未到视频生成。

|---|---|---|---|---|

四次独立物理执行、2,351 个状态帧、8 路同步相机视频；12/12 个预设反例被同一验收 v3 拒绝，无新增原生模型偏差。记录器与规划器复用已有实现；没有另写一套规划器。这里验证的是已有谓词、运动学及导出范围，不是所有连续碰撞或任意接触任务的证明。

首图输出的错误字段包括 `result` 替代 `value`、`candidate_frames` / `actual_frame_indices` 替代 `frame_indices`，以及缺失 `limitations`。四个完整响应均有真实 `STOP`，不是流式截断。严格校验拒绝它们是正确行为。不能从返回的若干肯定文字推导图片合格，也不能把这种格式故障当作四张图片视觉失败。

开发资格视频实际生成成功。49 帧审核通过；agent 在查看全图与局部帧后，未发现机器人残留、额外人物或手侧冲突，看到右手持续持钩、货物向目标垫移动、非目标货物保持。该观察未对方法盲测，不能证明每帧连续性、真实三维接触力或完整质量。它只支持远程条件接入与这个样本的采样可见性。

新机制仍没有完整真人来源对应。**正式 Real→Sim→Human 配对为 0，训练准入为 0。**

## 3. 接口故障诊断与修复证据

四个原失败先按原规则保存为 unknown，两组视频都不提交。`motion_r2` 仅增加完整 schema 失败的隔离处理；完整响应、请求绑定及原 schema 错误必须复现后才可继续其他案例。响应丢失、未结束或不明提交仍停止。没有伪造成功结果、字段重命名或补齐缺失证据。

之后单独登记接口试验：

| 探针 | 原参数 `responseJsonSchema` | 候选参数 `responseSchema` |
|---|---|---|
| 简单对象，包含只在 schema 中出现的固定标记 | 不合格 | 合格 |
| 嵌套审核数组及限制说明，包含固定标记 | 不合格 | 合格 |

每对只改变参数名；实际发出的 `generationConfig` 和请求内容均保存校验记录。探针没有图片，不能用于估计视觉准确率。Google 的[结构化输出文档](https://ai.google.dev/gemini-api/docs/generate-content/structured-output?hl=en)支持 JSON Schema 和流式结构化输出；本轮结论只针对实际供应商路径、模型及此次调用，不能推断官方接口普遍不支持 `responseJsonSchema`。供应商内部是否丢弃字段仍无服务器证据。

共享候选 `review_wire_r1`：

- `review_transport.generation_config` 保持原 schema 内容，按显式配置选择参数。默认仍为原参数；候选要求绑定同模型、同 base URL 的实际探针资格证据。
- `models.reviewed_json` 的真实入口采用该配置，并核对实际发出的图片、文字及 `generationConfig`，保存 payload hash。没有运行时自动切换或重发。
- 原 `review.py`、`hand_review.py`、`mechanism_review.py`、物理规则均未更改，unknown、对象 ID、帧引用等本地检查仍保留。
- 两张历史图片走真实入口，格式 2/2 合格；双人苹果图被人物结构子集拒绝，旧单人钩取首图通过同一子集。旧结果不被覆盖，也不据此重启旧任务。属于已知开发正负例回归，不是盲测检出率；完整场景、对象、手侧和 49 帧视频审核尚需新资格验证。

全部 **148 项本地测试通过**。新增测试覆盖媒体字节绑定、完整失败恢复与禁止重发、原参数默认行为、候选探针门禁及证据篡改。四个实际格式失败已作为带原始响应绑定的回归集重放。软件测试与已知案例回放不计为新增生成成功数。

16 次模型调用对应 17 条供应商消费记录，视频含提交与终态调整记录。三个批次的阶段扣额、服务商消费合计均一致。按公开单位 500,000 quota/USD 换算的是名义美元，**人民币现金实付仍 unknown**；不能把 token 数换算为人民币。

主试验原上限 image 4 / video 9 / review 13；实际剩余 video 8 / review 8，因原定案例终态而未使用，不能拿剩余额度重开失败样本。另两个诊断批次各自登记 review 4 / review 2，用途分别为格式因果对照及历史正负例接线回归，不生成替代任务。三批结束后累计谱系为 **image 28 / video 20 / review 44**。

主试验设置观察扣额止损 40,000,000 单位，另两个批次为 3,000,000 / 1,000,000；每次新调用前还保留预留量。这是依据已观察扣额的准入限制，不是供应商最终账单保证。历史上限与实际余量均保留。

目前更值得优先修正的批量阻塞是**审核协议可靠性**。视频生成与审核的分钟级等待仍是主要云端时间项，但本轮未形成有效配对，不能计算“每条有效配对成本”，更不能说费用或时间是唯一主要瓶颈。

## 5. 人工参与、版本与决策

逐任务生成 prompt 覆盖 0，手写新事件标注 0，内容重抽 0。仍发生了共享研发介入：原生 runner 的依赖激活遗漏在物理调用前修复；完整审核格式失败隔离；供应商参数对照及共享兼容适配。agent 还对资格视频和历史回归图做了后验查看。因此不能将整轮宣称为无人值守成功生产。

- 原生执行使用已冻结 `general_r1`；初始 runner 在预留物理次数前报依赖错误，失败日志与修正版快照均保留，不计为第五次物理执行。
- `motion_r1`：53 模块，实际生成一个资格视频、准备四组条件。
- `motion_r2`：53 模块，仅编排模块相对 r1 改动；处理完整无效审核并继续其他冻结案例。
- `schema_probe_r1`：54 模块，四个实际接口探针。
- `review_wire_r1`：55 模块，候选审核入口通过两个历史图片子集回归。默认参数和默认生成策略未晋级。

**保留**运动参考接入、累计账本、字节审计和失败隔离。**保留为 opt-in 候选** `responseSchema` 兼容路径。**不晋级**运动参考为默认条件，因为完整配对 A/B 没有形成；不宣称跨机制收益、任意任务能力、单人问题全面解决或新检测器泛化。

下一轮先在新登记的审核资格样本上验证完整首图与 49 帧视频协议，包括漏动作、错目标、错误手侧等负例；通过后冻结新布局做四机制 A/B。原四个格式失败案例可作协议回归，不能被静默重开或替换成成功分母。未来至少要区分人物/对象退化、过程完成、格式故障和审核误判。论文正文未据本轮增加成功率或训练收益。
