# 跨任务过程证据：2026-10-24 本地实现与回放

本轮回答的问题是：过程条件与工具化检查能否服务多类任务，而不仅修好一条搅动视频。结论是**已有任务声明可以复用同一套证据编译逻辑，但生成收益与视觉检测泛化尚未验证**。当前候选 `general_r1` 保留原生成提示、原生物理验收与视频审核标准，没有晋级默认质量管线。

## 应当复用什么

需要分开三层信息：任务目标及对象角色、必须成立的交互过程、某次机器人的具体走法。前两层可以约束合成人类视频，第三层通常只是实现方式。例如搬运保留源物体与目标位置；持续支撑保留操作期间不能松手；搅动只有在任务明确要求时才约束圈数。不能因为机器人碰巧走了一圈，就给任意“混匀”任务增加精确一圈的目标。旧基准已经声明的一圈要求仍完整保留。

共享规则根据合同的事件、关系与持续约束选择证据，不按任务名称、场景 ID 或颜色分支。仿真轨迹和功能几何可提供定位线索；生成画面中的实际对象、手和功能部件仍需重新定位，不能将仿真投影直接当作人类视频的正确像素。

| 可复用的检查 | 本轮覆盖的已有分支 | 可迁移方向；尚非新的视觉验证 |
|---|---:|---|
| 人物／手侧、对象身份、声明的事件顺序、初终关系 | 28 | 所有当前任务的公共要求 |
| 相对关节变化 | 14 | 按钮、拨杆、滑块、旋钮、杠杆；以后可扩展门与抽屉 |
| 持续持握或禁止直接抓取 | 14 | 工具使用、滚动；以后可扩展双手支撑 |
| 接触与运动先后关系 | 9 | 钩取、扫动、搅动；以后可扩展接触传播 |
| 已声明的功能路径顺序 | 6 | 描画、搅动；以后可扩展沿线擦拭 |
| 已明确声明的方向、圈数及额外运动 | 3 | 本轮搅动；以后可扩展绕圈与重复转动 |

各行重叠，不能相加成独立任务数。插入／间隙的证据类型已实现选择逻辑，但本次 28 分支没有插接，不能计为本次数据回放覆盖。

## 实际代码改动

- `evidence_plan.py`：从原合同编译 `human_evidence_plan`，逐条关联需要什么证据、是否需要在生成画面重新定位、当前能力限制。未知事件／关系明确列为不支持。缺证据应保留 unknown，不能因为得到一份计划就判定成功。
- `mechanism_conditions.compile_candidate`：实际合同编译入口附带上述计划。`paid_pilot.compile_all` 保存并绑定独立 `evidence_plan.json`，未覆盖已知声明时停止准备生成。这个入口接入的是准备逻辑，本轮没有执行新的生成或视觉审核。
- `motion_evidence.py`：接受时间戳、二维点、相对中心、可见性，分别测量正向、反向、净角度和总角运动。缺失片段不插值补圈；时间断裂和过大角度跳变明确报告。它不负责找工具、不证明接触，也不输出视频通过判定。
- `tools/replay_general_evidence.py`：使用保留的原生合格任务清单，执行跨机制合同回放、旧生成条件一致性检查、旧轨迹测量诊断。

新功能没有取代独立验收器。模型、图片／视频生成模式、原视频审核谓词、物理验收阈值均未修改。当前 motion-reference 仅为研究假设标记，尚未实现或验证新的远程生成路径。

## 实际验证

实验根：`/mnt/sdg/datasets/real_sim_human_pipeline/general_evidence_20261024_v1/`。

1. 全部 **133 项本地测试通过**，其中 16 项新增测试检查按声明分派、未知机制、对象引用、净转角陷阱、缺失观测和测量边界。测试证明代码行为，不是视觉识别率。
2. 既有十类机制的 **28 个合格任务分支**通过同一编译器，声明覆盖完整，原生验收信息与真人来源映射不变。十类分别为弹性按压、拨杆、滑块、旋钮、杠杆、滚动、钩取、扫动、描画、颗粒搅动。
3. 与上一付费轮的 **6 份输入**逐一比较：`generation_information`、`initial_scene_information` 和完整视频 prompt 保持一致。旧失败和原审核结果均保留。
4. 两条旧搅动视频的 49 点颜色诊断轨迹接入通用角运动测量后，均为 **unresolved**：存在无效观测和过大相邻角度跳变，不能据此认证整个区间的精确圈数。原提点仍依赖蓝容器／木色工具，未因此变成通用视觉检测器；旧的约 1.84／2.88 圈仍只属于后验诊断。
5. 数学反例验证：正向两圈再反向一圈，净值仍为一圈，而累计运动为三圈。单看净值或首尾相同会遗漏额外运动。实际视觉噪声也会放大累计运动，因此本轮没有引入自动通过阈值。

以上为已有开发数据的本地回放，文件名中的 `validation` 是此前原生实验的阶段名，**不是此次独立保留验证集**。本轮新增 API 调用 0、仿真执行 0、生成视频 0；没有新的生成质量结论或正式配对。上一付费轮账本不变：谱系 image 24 / video 19 / review 33；该付费轮名义消耗 31.289674 USD，人民币实付 unknown。

## 为什么有益，以及仍可能无益的地方

主要预期收益是减少“每种任务补一个特例”的维护工作，避免已知的过程约束在图像／视频生成和审核之间丢失，并将不确定性留在具体证据上。这不等于任何任务都应加入更多条件。简单搬运可能只需清楚的角色、接触和放置关系；增加完整运动参考可能徒增费用，还可能把机器人结构带进人类视频。精确路径、持续接触、关节复位等任务更值得优先做过程条件对照。

它也不会解决缺少可用资产、资产功能定义错误、控制器能力不足、软体／流体机制缺失或真人来源不完整等上游问题。生成画面的稳定定位、手部归属、遮挡后的身份恢复仍是未完成能力。当前只能说明工程抽象可复用，不能说已经提高多任务有效产率。

## 下一步证据要求

先将生成条件与审核改动分开比较。选择至少四种不同交互机制，在新布局、尺寸或颜色上冻结对照输入；旧按钮与搅动作为开发素材，不把旧回放重新称为保留验证。固定同一新版验收器同时比较基线与候选，并保留无动作、错目标、额外循环、方向反转等对照。

过程条件候选可比较“首图＋文字”和“同一人物外观参考＋仿真运动参考”，但必须先核对实际供应商的引用模式与付费接口资格；本轮未做这项调用。不能假设参考视频可直接与 first/last-frame 模式混用。人物数量、手侧、对象保持和不必要的机械臂外观也要作为可能退化项检查。

晋级依据是不同机制／新布局下每次尝试的独立合格产出、每条有效数据的时间和实际费用、人工介入次数，以及分类误报／漏报。不以 VLM 分数升高、合同字段增多或回放数量作为质量提升。跨机制收益未出现时，应缩小使用范围或放弃额外条件，而不是把所有任务强行套入同一生成路线。
