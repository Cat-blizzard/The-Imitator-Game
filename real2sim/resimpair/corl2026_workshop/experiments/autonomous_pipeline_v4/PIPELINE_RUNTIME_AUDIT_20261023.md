# 2026-10-23：任意任务的能力边界与实际运行耗时

当前系统已能在适配过的场景和机制中自动生成、编译、调用模型并形成有证据的终态，**还不能承诺任意真人任务直接得到合格人机配对**。最主要的问题是机制覆盖、生成时的事件/对象/身体约束，以及视觉审核的可靠性。已适配任务的机器运行时间则主要消耗在视频和审核服务。

本轮只读核对两批 ledger：`autonomous_multitask_20261023_v4`、`autonomous_mechanisms_20261023_v5`。共 **33 次实际启动的 API 调用、17 次仿真尝试、6 条人类视频**；没有重新生成、重跑物理或修改旧判定。时间来自明确的计时字段/调用时间戳，缺失不填零，不把文件修改时间当运行时间。

## 任意抽取任务可能遇到什么

| 环节 | 当前实际能力 | 随机任务最可能出现的问题 |
|---|---|---|
| 真人窗口与语义 | 已登记窗口按固定 24 帧抽样，模型输出身份、角色、事件、功能几何、技能和不确定性；当前这两批合计 5 个自动来源窗口 | 不是从任意长视频中自动保证找到完整任务。遮挡、短暂接触和前后状态可能漏采；JSON/引用有效不证明语义正确 |
| 来源到新任务 | `select_sources` 按技能覆盖选择来源，允许改变场景和组合任务；显式标记 `exact_source_episode_equivalence=false` | 覆盖了 pick_place/insert 等技能，不等于保留原任务全部目标和必要步骤。例如开门再取物不能只保留开门就声称整个任务对应 |
| 资产与机制适配 | 当前共享场景用程序化物体、支持物、刚性接口、关节对象；有明确几何与测量导出 | 有一个 mesh 不等于可抓、可开合或可插接。新资产的尺度、碰撞、关节、抓取面和目标接口需适配；历史资产预检数量不等于当前脚本可执行机制数 |
| 规划与执行 | 搬运/堆叠/排列等复用 pick_place；另有连锁、持续持握插接、盖板规划分支 | 新接触机制、细小/遮挡抓取、重复操作同物、长偏序任务可能缺适配器。盖板已有三次失败，其中一次有 IK 弧却没有真实抓持。IK 成功不能替代抓取成功 |
| 人类图与视频 | 初图及结构化文本生成视频；事件、目标、对象与手侧有声明 | 视频服务实际没有被机器人轨迹逐帧约束，仍可从错误多米诺端点触发、复制物体、交换操作手、改变功能孔。最新手侧修复只经本地验证；当前几何映射限于同向并排 Panda |
| 验收与修复 | 原生物理谓词、帧/来源绑定、49 帧 VLM 审核、结构化计数/手部记录；内容失败为终态 | VLM 曾漏掉物体复制、判反人体左右，稀疏帧也不能证明全程接触。新增手部审核的远程 schema 与准确率仍待验证；不能以一次全 yes 宣称合格 |

目前来源技能枚举为 `pick_place / stack_on_support / push / articulate / insert`。倒液体、柔性物、工具使用等没有因为模型能描述就自动获得可靠仿真与验收支持。对新任务应首先确定“现成支持、需新资产适配、需新机制实现、当前不支持/证据不足”，再决定是否值得付费生成。

## 从真实记录得到的时间

| 部分 | 已记录耗时 | 分母和口径 |
|---|---:|---|
| 真人来源提取 | 58–110 秒/窗口 | 5 次、每次 24 帧；模型 HTTP 时间，未包含找视频/筛窗口或人工研发 |
| 成功仿真脚本 | 18–76 秒/次 | 12 次完成导出；包含进程启动、环境、规划、执行、双视角记录和导出。多数约 25–37 秒；不等于 12 种独立动作 |
| 失败仿真尝试 | 6–557 秒/次 | 5 次；最慢一次约 9.3 分钟但 supervisor 未标超时，不能擅自写成 timeout。两条旧 `executed` 标签与实际规划失败矛盾，统计依据真实失败和 worker 结果 |
| 人类首图生成 | 30–39 秒/张 | 3 次 HTTP 调用，首图可在同初态任务间复用 |
| 首图审核 | 22–49 秒/张 | 3 次 HTTP 调用 |
| 视频提交至首次审核开始 | 221–287 秒，即 3.7–4.8 分钟 | 6 条；包含服务排队/生成、轮询、下载、抽帧和中间编排。不是纯模型计算，也没有独立下载计时 |
| 首次视频审核 | 旧批 35–100 秒；新机制批 136–201 秒 | 均为 49 帧；分别 n=4 与 n=2，任务/提示/schema/服务状态不同，不能直接归因于某个改动 |
| 后验重审/接口失败 | 单列，不混进首次生成平均 | 7 次失败重审约 8–65 秒，另有 2 次返回的重审和 1 次接口探针 |

以新工作台为例：多米诺的已记录阶段相加约 **9.1 分钟**（含首次共享首图），插接约 **7.4 分钟**（复用首图）。这不是一次从任意真人任务到合格配对的端到端实测：不含找源、实现适配器、此前失败、未记录的编排间隔等。两条视频均保留拒绝，不应把这个时间写成“每个有效配对成本”。

## 已补的测量能力

冻结候选为 `observability_r1`，继承 `hand_correspondence_r1`；代码在本目录，冻结副本在 `/mnt/sdg/datasets/real_sim_human_pipeline/pipeline_profile_20261023_v1/releases/observability_r1/`。计时不改变 prompt、物理谓词、审核标准、重试或预算规则。

- `profiling.py` 和 CLI `profile`：只读提取真实调用/进程时间，输出 JSON、CSV、Markdown；区分来源、共享首图、首次生成、后验重审、接口试探，以及失败和未知。明确样本数、最短/中位/最长，不用六个视频伪装稳定 P95。
- `timing.py`：每个阶段持久保存开始/完成，使用 monotonic duration；记录父子关系、缓存命中、技术异常类型和内容拒绝。中断缺少完成记录保留 unknown；不写 API key、签名 URL、请求正文或原始异常消息。
- 已接入来源抽帧/提取、合同与媒体验收、首图生成/审核、API 操作、视频轮询/下载、视频抽帧/审核、pipeline 调用，以及两套 worker 的环境初始化/reset、规划执行、视频收尾与测量导出。
- 每次视频轮询仍只查询既有任务，不新增 POST；以后有首次观察到终态的时间，可与提交、下载分别比较。服务内部排队与计算仍需供应商时间戳，不能仅凭轮询恢复精确边界。
- 仿真内部暂时仍把规划、执行与渲染放在同一计时段；不能声称已经测到纯 IK 或 GPU 内核时间。适配器研发/agent 人工介入时间需从今后开始单独记录，不能从旧文件时间倒推。

本地 **65 项测试通过**（新增 10 项），覆盖错误保留、敏感信息不落日志、墙钟回拨、崩溃/未知、缓存、父子计时、旧状态标签冲突、重审分组、重复 ledger 防重计数。没有为了验证计时而花费 API 或占用 GPU。

## 下一轮如何评价“任意抽取”

先冻结抽样名单和规则，按新颖程度分三层：已有技能的新布局；已有机制的新资产；全新交互机制。每个抽到的任务都保留在总分母里，包括不支持和不进入生成的任务，不能只统计最终生成出视频的子集。来源会话/物理执行/场景家族不跨数据划分。

每层分别记录：任务表示是否完整、是否需 agent 新写适配、物理通过、首图通过、任务/对象/人物/交互/连续性各项结果、未知项、最终合格配对数。记录每阶段机器时间、API 次数/实际费用、人工或 agent 介入次数与活动时长；重审、重试、修复实验分别标记。内容失败仍终止，不以自动重抽提高表面通过率。

对质量检查建立冻结的独立正负例和逐项参考判断，报告漏检、误拒与 unknown。正面生成结果也要抽查，尤其是复制物体、错误接口、跨身手侧和接触短暂丢失；不能只给已知失败加一个更长 prompt。

我的优先级：先完善任务支持/缺项判定和可靠审核，再做新增机制的小规模对照。已有任务减少延迟可研究按事件选帧或分层审核，但只能作为候选，在保留相同验收要求的情况下比较漏检/误拒；本轮未减少帧数或放宽门禁。并行度也不应仅为加速而突破当前预算/并发配置。
