## 本轮实现与基线

基线是 `active_asset_r2`，保留在原实验根中。本轮候选 `scene_pilot_r1` 含 36 个 Python 模块；90 项冻结代码测试通过。修改前开发树和入口状态保存在 `corl2026_workshop/revisions/20261024_scene_task_pilot_v1/before/`。

- `scene_tasks.py` 从实际场景枚举搬运、装盘、分类、堆叠、排列候选，检查物体净空、支撑物 XY 容量、保守工作区、目标占用及已有接触适配范围。每个场景 30 个候选；A/B/C 分别 10/6/6 个通过静态筛选。按固定种子选择三个目标不同、模板不同的任务。完整候选池、拒绝原因和抽取结果均先于执行保存。此筛选不证明路径、抓持或稳定性。
- `scene_pilot.py` 接通准备、冻结、逐项物理执行、编译、零预算门禁及场景任务打包。每个任务都从同一场景文件独立重置，GPU 2 串行、每项一次、180 秒超时，无失败替补。每次启动沿用原 GPU UUID／任务锁检查。
- `compiler.completed_contract()` 和生成入口补完整性检查。旧入口可能因为 `contract.json` 已写出而跳过尚未完成的视频解码；现在两路完整解码、媒体绑定、原生 PTS、帧数、相机参数及抽帧证据缺一不可。故障测试确认半成品合同不能进入付费生成。
- 场景任务包按实际 scene、task、execution、contract、source 和 release 绑定，不使用跨布局的 `semantic_key` 借用视频。旧 `report` 的语义覆盖清单仍是不同用途；这轮严格配对使用 `scene-package` 输出。人类尚未生成，因此不能把仿真合格数称为有效人机配对数。

原仿真求解器、事件谓词、规划合同、主动资产验收、手对应及视觉审核文件与基线字节一致。本轮没有为提高通过率改控制或放宽门槛。编译完成性属于新加严的运行门禁。

共 6,375 个状态、6,366 个原生动作、18 条同步视角视频。两路相机是同一次物理执行的记录，不计为两条独立动作轨迹。五种任务模板仍主要共享抓取／搬运／释放原语，不等于五种新接触机制；本轮没有加入新双臂并发控制。

独立复查重新计算原物理谓词、FK、主动碰撞网格与动力参数，并完整解码 18 条视频。三组各自的原生初态、物体状态、两路首帧均完全一致。八条合格轨迹之间做 14 个同场景错任务合同反例，均拒绝。重复运行完成批次入口后仍为原九次尝试，reservation／terminal 绑定未变，API 调用仍为零。

牛奶盒六次新布局任务中，六次原生几何验收通过、五次任务完整通过；这扩大了上一轮单个开发实例的局部证据，**不修改源 catalog 的全局资格**。旧 `active_milk_layout_validation` 仍未执行；这次是新任务和 r2 描述的新绑定，不回填旧试验。

来源合同全部复用历史 train 会话；新增来源提取为零。这里验证的是冻结代码后的新布局执行，不能称为独立真人来源验证，也不能把本批 8/9 推广为任意任务成功率。

## 失败定位与下一次控制改进

失败为 `scene_B__arrange_7264139b8142b3c0`。控制脚本完成并不等于物理资格通过：原门禁拒绝最终位置、直立稳定性和持握至到位的约束。原终态、视频、请求前证据全部保留。

- 牛奶盒落放期间已经倾斜；第 310 个状态仍被夹持，但距目标 21.9 mm，直立方向点积约 0.894，未达到原要求 15 mm／0.95。
- 第 311 个状态来自首次开夹命令，抓持变为 false；第 328 帧才短暂进入目标位置阈值，第 340 帧已经倾倒。
- 最终位置误差约 71.7 mm。同场景中蓝块位置合格；另一布局 C 的同类排列成功，说明失败与当前资产／姿态／落放路径组合有关，不是所有排列都不支持。
- 更早的“搬运中未持续持握”是验收项描述。逐帧定位将具体问题收敛到**落放与松手之间**；还不能据此区分接触、夹持滑移和控制跟踪各占多少原因。

最便宜的下一步诊断已完成：在真实记录的每次开夹前，用原目标距离和直立阈值检查位姿及抓持。15 次放置中只触发上述牛奶盒一次；来自八个整体合格任务的 13 次放置均不触发。另一项是失败任务中的蓝块放置，也不触发。`failure_regression.json` 按操作保存该失败执行的两份观察，失败物理执行仍只计一次。

这项[离线回放](/mnt/sdg/datasets/real_sim_human_pipeline/scene_task_pilot_20261024_v1_audit/diagnosis/release_preconditions.json)只是修复假设的诊断证据，未改控制器、未产生新轨迹。下一候选应在松手前读取物体位姿／抓持，状态不符则停止并保存失败；必要的落放调整应有明确次数上限，并在新布局、新保留样本上实测。提前停止本身只能减少错误释放，不能宣称提高成功率。

## 耗时与人类生成准备

九项逐项处理累计 **300.35 秒，约 5 分钟**，包含物理进程、编译和本地条件准备，不包含本轮开发／测试／独立审计。物理 worker 合计 287.01 秒，单项 22.75–37.82 秒。

| 阶段 | 本批单项耗时 | 范围说明 |
|---|---:|---|
| 环境初始化 | 5.78–6.85 秒 | 不含 Python/依赖导入等进程启动余量 |
| 重置及记录器 | 0.76–0.89 秒 | 同场景每个任务仍独立初始化 |
| 规划＋执行＋渲染 | 12.64–26.67 秒 | 下三项为内部独占计时，不能再与本行相加 |
| 其中：渲染与读回 | 7.31–15.74 秒 | 双相机、逐帧记录 |
| 其中：状态／接触测量 | 3.41–7.08 秒 | 原有测量频率与语义不变 |
| 其中：物理控制 | 0.78–1.79 秒 | 含控制与接触 bookkeeping |
| 合同＋双视角完整解码 | 0.79–1.35 秒 | 仅八条合格任务；拒绝任务在 0.09 秒提前停止 |
| 新人类首图／视频／审核 | 未运行 | 新预算均为 0，不填估计成本或时间 |

实际路径求解合计约 1.25 秒，是九项简单任务全部 screw/RRT/return 的和；不能外推到复杂接触、障碍密集规划。当前本地主要开销仍在渲染、测量和环境建立，优化前须保留逐帧测量与同步证据。

准备了 **3 份共享首图条件、8 份逐任务视频条件及审核清单**。同场景的合格任务确实得到同一个 anchor ID；失败任务不生成条件。准备文件位于实验根的 `prepared/anchors/` 和 `prepared/tasks/`，均标注未提交。实际生成入口的零预算检查已执行，八项均返回 `awaiting_budget_capacity`，没有 provider 提交。

新增付费 API 调用为 0，祖先累计 image21/video13/review24 保留。本地计算未折算人民币；有效人机配对为 0，所以每有效配对耗时／费用不可计算。新版单人身体、操作手对应及视觉审核的生成收益依然没有新证据。
