# cuDex-graspvla、抓取质量与批量任务：2026-10-26

后续更新：2026-10-27 已运行实际 cuDex CUDA 优化和原生物理对照，见[新结果](../validation/cudex_physical_20261026/RESULTS.md)。以下保留本轮仅做离线静力代理研究时的结论和预算时间范围；不得将两个方法／实验合并。

本轮核对了用户指定的 [MiYanDoris/cudex-graspvla](https://github.com/MiYanDoris/cudex-graspvla)，固定提交 `e3d84aea7ee6c87df99b4f980cac8b6a52b2d362`。本地候选分支为 `candidate/cudex-grasp-quality-20261026`。主线、物理控制器、原选臂器、闭合检查和独立验收器均未替换。结果见 [RESULTS.json](../validation/cudex_contact_quality_20261026/RESULTS.json)，源码位置与哈希见 [来源记录](../validation/cudex_contact_quality_20261026/RESEARCH_SOURCES.json)。

**这个仓库实际怎样生成 pose**

1. 输入加工后的物体网格、物体尺度／重心信息、桌面姿态和机器人几何。仓库配置引用外部资产路径；它不负责从任意视频识别任务，也不自动补齐原始资产的功能语义。
2. `HeurGraspSeedGenerator` 用表面点、法线和 Halton 低差异采样构造初始手位姿，并扰动平移、旋转和指关节。Franka 配置有 1,000 个 seed，优化文件配置 500 次迭代。
3. 联合优化手的浮动位姿和关节，使预期接触点靠近物体，同时考虑接触能量、距离、碰撞与关节边界。Franka 接触目标从 5 mm 间隙过渡到接触；其两阶段 `contact_query_mode` 都是 `-1`，即球体接触查询。
4. **这个 fork 的 Franka 默认能量是 DFC**。源码对等大小接触法线构成的合力／归一化合力矩求残差。它并没有使用配置里的目标载荷求解 QP；不能把新版 BODex 的完整 QP、精细接触网格流程当成该配置已经开启的能力。
5. 求解器有碰撞可行性、抓取误差和接触距离的成功标记。但示例脚本请求返回全部 seed，并保存姿态及误差，没有在输出里显式保存 `result.success`；失败只是排序靠后。因此若接入原始 npy，必须补回成功标记并再次执行本项目独立检查，不能把文件里的每个 pose 都算有效。
6. 配置使用 `franka_with_gripper_extensions.urdf`，浮动根是 `panda_hand`，`ee_link` 是左指，**不等于本项目原生 Panda wristcam 的 TCP**。延长指、接触点、关节联动和坐标变换必须重新适配；直接复制位姿数值会复现“理论接触点能夹、实体手指先碰到别处”的问题。

对应的 [GraspVLA 论文](https://arxiv.org/html/2505.03233v1) 将抓取合成、cuRobo 轨迹规划、MuJoCo 抓取抬升检查和渲染分开。[BODex 论文](https://arxiv.org/html/2412.16490v2) 展示了力学优化和不同重力方向的物理检查。它们的数据量或抓取成绩不能直接证明本项目的容器内释放、多步任务或合成人类视频质量。

本轮没有运行上游 GPU 优化器。源码可获取，但其机器人／物体资产目录未随该小型仓库提供，安装说明使用旧 PyTorch/CUDA，仍需独立环境与原生 Panda 适配。没有把“克隆成功”记为“接入运行成功”，也没有为安装它改动现有环境。BODex 当前 README 推荐后续 Dexonomy；对灵巧手可另立比较，不能把灵巧手结果直接外推平行夹爪。

**本轮实现与对照**

当前离线库已有 24,000 个网格处理记录、11,461 个含候选的资产、456,339 个 pose。本轮重点是候选质量与使用方式，没有重复扩量或重新实现桌面姿态库。

- `contact_refinement.py`：以已有 pose 为起点，在切向位置、抓取高度、yaw 附近进行有界低差异搜索；用原生碰撞网格重新求接触，并调用原来的实体手指闭合和开手接近检查。最多 8 个来源、每资产 180 秒、CPU 串行，不重跑失败来源。
- `contact_quality.py`：显式求解静力载荷平衡，比较两个摩擦假设、搬运方向和 ±2 mm 重心扰动下的最差承载代理值。每指 1 N 法向力是归一化评分预算，4 mm 接触斑半径是工程假设，不是实际接触测量。点接触结果另行保存，不能把软指假设隐藏起来。
- `quality_reachability.py`：独立候选入口，将排序传给联合源／目标选臂；仍要求原来的端点 IK 和容器开手净空。旧 `reachability.py` 字节保持一致，默认任务继续使用原选择器。
- `batch_diagnostics.py`：只读汇总登记、预检拒绝、物理执行、失败、未知状态和分阶段排他耗时。支持反复用于新批次，保留失败分母和缺失证据。

预先冻结 2 个开发来源和 6 个保留来源，分为“原首选”“原池只重排”“原池＋局部新候选”三个离线对照；所有姿态用同一新模型检查，没有修改原独立物理规则。8 个来源均完成，6 个有新缓存，共 56 个候选。单来源进程耗时中位数 1.74 秒，串行总计约 17 秒；这只覆盖已有原生资产上的分析，不含冷启动碰撞转换、轨迹执行、渲染或人类生成。

4 个来源的重排结果在所声明的静力代理值上优于原首选；局部搜索在 1 个来源上进一步优于重排，另恢复了 1 个在该模型下无可用原候选的来源。**这不是物理抓取成功率提升。**

发现的重要反例：`abo:B07TX2D39D` 在上一轮实际抓放成功，本轮低摩擦／简化接触模型却不保留其原候选。一个原生接触面的方向余弦为 0.983，低于本轮 μ=0.15 假设对应的约 0.989 门槛；局部新候选也没有在所设载荷和接触斑假设下取得正容量。支架原生碰撞面的局部法线也与视觉网格差异很大。3 mm 的表面位置误差验收不能保证法线、曲率和接触区域保真。

因此决策是：保留离线搜索、代理值及诊断工具作为候选，**不把这组低摩擦模型升级为生产硬门槛**。被模型排除不等于实际抓不住，原来物理有效的资产和记录继续保留。相同两条旧验证输入的候选端点预检为 1/2，另一条因候选缺失而拒绝；没有省略该结果。

数学回归还展示：对称两点接触在重心偏移前后可以具有完全相同的 DFC 残差，但承受重力的能力明显不同。详见 [反例](../validation/cudex_contact_quality_20261026/dfc_counterexample.json)。这说明有必要增加任务载荷与重心信息；它不能证明这一个代理模型已经足够准确。

**批量任务还缺什么，优先怎样补**

| 优先级 | 代码／实测暴露的缺口 | 合适的下一步与验收依据 |
|---|---|---|
| P0 | 碰撞外表面通过，不保证接触法线与接触斑可靠；重心、摩擦多为工程假设 | 对少量不同形状的资产记录真实原生接触和 COM，做夹持扰动校准。比较原排序、重排、局部优化，验证集另取；只改善代理值不晋级 |
| P0 | 能抓住的 pose 不一定能进入目标容器并撤手 | 把抓取、目标姿态、手指开口和撤手作为联合候选；在物理执行前排除不可达组合。保留现有支撑面检查，不靠抓取优化掩盖坏容器 |
| P1 | 当前 `composition.py` 每物体只搬一次，拒绝多个物体进入同一容器 | 增加容器可用区域、容量和互不重叠的放置位；维护任务过程中的占用状态。这样才能支持收集、装箱和更丰富的同场景任务，而不是只换物体名字 |
| P1 | 抓取缓存可复用，但冷资产转换仍有长尾；分类、来源、尺度与机制覆盖不等价 | 任务需求驱动的转换队列、按几何／夹爪／尺度／质量假设版本缓存、失败原因缓存；分层抽样记录资产覆盖和机制覆盖，避免只抽最容易的资产 |
| P1 | 当前随机干扰物以不侵入工作区为主要约束 | 在独立组逐步增加密度，以整手和携物扫掠体校验路径；先规划失败分析，再决定是否需要主动清障技能。不要把背景资产数量当成接触机制增加 |
| P1 | 当前仿真时间中渲染和状态记录占有明显份额 | 先分析同步开销，复用同一控制步内的状态读取，减少重复设备回读，复用环境和编码队列。必须比较动作、时间戳、接触证据及相机参数完整性，不能通过丢关键帧伪造提速 |
| P0（配对） | 新组合导出仍明确标为 `synthetic_only`，人类视频也需要保持角色、单人结构和关键事件 | 用已通过物理验收的事件／角色／手侧编译条件；人类生成按这些维度独立审核。没有真人来源绑定时保持缺失，不将任意新任务称为 real→sim 已对应配对 |

8 条上一轮保留任务的平均排他耗时：RRT＋screw 规划约 1.67 秒，独立密集碰撞检查 2.12 秒，物理控制与接触 2.13 秒，双视角渲染回读 5.82 秒，状态／接触测量 5.03 秒。数据见 [历史保留组统计](../validation/cudex_contact_quality_20261026/heldout_baseline_timing.json)。这些是有缓存的小任务，不能外推任意任务或整个人类视频流程；排他统计外还存在启动等未归属开销。

本轮只读诊断覆盖 23 个历史登记案例：5 个预检拒绝、18 次实际执行，已有独立审计中 13 个通过、3 个失败，2 个没有相应审计文件。缺失没有记为通过。该集合是选定历史实验，并非全库随机成功率。

**运行入口与限制**

```bash
# 已加工资产上的离线优化。selection.json 绑定来源、数据划分和有限配置。
.venv/bin/python -m resimpair_pickplace.contact_refinement run \
  --plan <selection.json> --output <new_output>

# 显式候选选臂／端点检查，保留原输入；不执行仿真。
.venv/bin/python -m resimpair_pickplace.quality_reachability \
  --scene <scene.json> --task <task.json> \
  --index <new_output/cache_index.json> --output <new_preflight>

# 汇总已有批次；不提交 API 或仿真。
.venv/bin/python -m resimpair_pickplace.batch_diagnostics \
  --campaign <campaign_a> --campaign <campaign_b> --output <new_report.json>
```

340 项测试和 85 个子测试通过。本轮物理执行 0、GPU 任务 0、收费 API 0；先前共享物理累计仍为 24/24。没有新策略训练、人类视频或正式配对。下一阶段应先登记有限的、继承累计谱系的物理验证协议，再比较真实夹持扰动与完整放置成功，不能通过新目录绕过已耗尽额度。
