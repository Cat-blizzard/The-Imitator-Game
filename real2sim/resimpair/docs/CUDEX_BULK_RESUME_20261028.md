## 根因与修复

v2 诊断先算 signed ESDF，再在同一个 `CollisionQueryBuffer` 上计算非负碰撞代价。上游 cuboid CUDA 内核的 ESDF 分支写入负距离，但没有设置稀疏标志；下一次安全点的零代价分支可能直接返回，留下旧负数。实际保存的 76,032 个桌面 primitive 缓冲值在两种模式下逐项完全相同，均为负数；mesh 的新代价则非负。

这属于跨计算模式复用缓冲区的错误，不是这一资产无法抓取的证据。把总和截断为零会掩盖 mesh 碰撞，因此未采用。

`resimpair_grasp/cudex_constraint_v3.py` 为每种模式单独分配清零缓冲，并在 `finally` 恢复优化器原始缓冲与模式。诊断前先保存完整未排序 q 和接触结果；即便诊断失败，正常排序输出也尽量落盘。GPU 求解结束后退出进程，再由独立 CPU 阶段检查、导出缓存，避免 CPU 几何检查继续持有 GPU。

新候选仍使用已冻结的原生 Panda 几何、TCP 变换、种子、代价和阈值。资格对照沿用原固定四个来源，比较 signed 与 nonnegative 两个约束配置；非负配置更改的是约束解释，不把原 `success` 改名为成功。

CPU 导出调用既有 `common_native_hand_6d_v1` 规则，检查全部 256 个原始 pose。检查原生手掌/手指、桌面和沿世界 Z 的接近扫掠，以及闭合时能否到达相对接触。姿态不平移、不吸附；空缓存仍保留在分母。缓存只声明几何候选，稳定抓持、搬运、释放和完整任务成功仍是未验证。

## 全量队列与资源约束

`resimpair_tasks/cudex_bulk_queue_v2.py` 将固定四来源的八个资格作业和全部 5,524 个候选资产登记在同一个不可变协议中。四个 nonnegative 资格结果复用于全量目录，因此最多新增 **5,528 次 GPU 作业**：8 次资格＋5,520 次其余资产。加上上述 142 次，扩量谱系上限 5,670；这不是整个项目所有历史实验的总数。

独立检查程序审查全部八个资格结果及原始数组、碰撞分量、q/pose 对应、缓存账，并在 CPU 上重新检查一个非空候选。检查通过后自动进入全量阶段，无需人工重新开批。失败则保留现场并停止，不降低规则换取通过。这个门槛只允许批量离线候选生成，不是默认管线晋级或动力学认证。

每次最多 1 个 GPU 求解、1 个 CPU 导出；每阶段超时 180 秒。首次接手 GPU 要求 120 秒无人占用观察、内存不超过 512 MiB、利用率不超过 10%，并取得项目锁。连续本队列作业会重新检查占用；一旦观察到外部占用就重新等待。GPU 求解使用 CUDA，资产加工和姿态检查使用 CPU；本轮不需要付费 API。不得使用已有训练任务的 GPU。

提交窗口最多七天，从首次启动固定计时，重启不清零。按资产、配置和代码内容注册同一配方，不能换目录重复获得预算。守护进程、子进程、启动时刻和锁均保留；已完成优化可直接接 CPU 导出，未确认作业禁止隐式重交。

`status.json` 保存当前状态；`counts.json` 是统计快照；每个作业有不可变请求、预约、阶段终结和结果。`candidate_cache_index.json` 保留已完成的候选，包括空缓存；`native_cache_index.json` 只列非空几何缓存，供现有打包和抓放任务入口读取。具体启动 PID、状态与目录以 `CURRENT_STATE.json.active_cudex_bulk_resume_20261028` 和队列实际文件为准，不能从此文推断所有 GPU 作业已经完成。
