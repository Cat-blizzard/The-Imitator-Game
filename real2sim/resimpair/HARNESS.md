# 持续研发与运行规则

目标是提高任务对应、物理执行、关键交互、人物与对象一致性以及有效配对产率，扩大机制、来源、布局和资产覆盖。当前不启动 HyperNet / PolicyNet 或其他策略训练。

每轮按“失败诊断 → 可区分假设 → 最小实现 → 保留基线的对照 → 根据证据保留/修改/放弃 → 写入持久状态”推进。开发样本与保留验证样本分开；同一真人来源、物理执行及其派生内容不能跨数据划分。

生成器和独立验收器分工明确。不得为提高通过率放宽同轮标准。修正规则漏洞时升级规则版本，并在同一新规则下重评基线和候选。首试、修复、外观变体、多视角、重复执行与独立动态轨迹分别计数。

人物数量、左右手归属、对象身份/尺度、接触与释放、状态顺序、连续性、相机/动作/状态时间轴分别验收。缺少证据标记 unknown；VLM 肯定回答不代替独立物理或像素证据，不要求人类 RGB 提供真实三维物理标签。

源输入、请求、响应、失败、已冻结 release 与旧产物不可覆盖。先小样验证再扩大；同一失败不通过换名字、换目录或重抽绕过统计。候选有实际跨输入验证后再晋级，发现退化可回退。

API 已获长期授权，无需逐次询问。每个新实验必须登记有限调用数、累计谱系、名义额度上限、并发 1 和超时；未知提交优先恢复查询，不能重新提交。实际费用由供应商消费记录和额度变化核对，人民币现金实付没有证据时保持 unknown。预算耗尽后转向本地分析，不规避预算。

复制/克隆代码不会转移正在运行的实验。保留 `runs/` 和 `runtime/` 账本；迁移后的运行记录若包含绝对绑定路径，必须显式迁移并核验，不能静默改写证据。原历史累计与打包验证调用已保存在 `provenance/`，新实验必须继承。

不移动旧数据腾空间，不占用已有训练的 GPU，不结束无关进程。执行前核对磁盘、任务锁与进程。报告说明做了什么、证据、未解决问题及下一步，不能以文件数量、实验次数或 VLM 分数替代实际改进。

场景诊断与修复优先使用 `scripts/scene_tools.sh` 的统一接口。修改操作顺序必须保持精确目标和必要先后约束；修改落点必须创建新目标/布局版本并更新来源合同，不能把它记作原精确目标的修复成功。离线碰撞资格、进程终态、独立物理合格和完整人类配对分开报告。准备任务已占用累计容量，未知提交必须恢复而不是重交；超大结果返回恢复路径时也不能把它当成提交失败。接口实现与候选输入分别冻结，后续修正接口不得覆盖原方案代码和实验结果。

2026-10-30 尺寸与用途原则：可信米制资产保留源尺寸；大型家具用于背景，不为适配夹爪自动缩成小物体。操作物允许有界尺寸变化，每个实际几何版本绑定自己的抓姿缓存，不能把旧抓姿在线等比例放大后直接复用。质量优先采用可信来源；缺少实测时明确记录工程假设，同类等比变体按质量 ∝ 尺度³、惯量 ∝ 尺度⁵处理，并检查有限性、用途负载和数量级。不要把静态背景家具套进夹爪动态负载上限。背景作为独立渲染层，不改动作、物理碰撞或相机绑定；成功样例拼图明确标注筛选口径，不冒充整体成功率。

2026-10-31 追溯补充：相对上一阶段的 scale=1 不等于原始下载尺寸未改，必须检查完整 source_to_asset 与上游归一化。原始网格单位不明时不能直接宣称坐标是米；明确区分可信元数据、公制来源惯例和工程推断。新 raw 接入不能继续依赖旧夹爪归一化资产池才能进入作业清单。场景需要更多容量时先改变容器/目标区域和明确的任务数量，不能静默缩小物体或换成更小物体掩盖容量缺口；报告尝试与拒绝的尺寸分布。

适合的非易碎收集任务允许在容器边沿上方释放，使用实测夹持变换计算物体落点和手部净空。仍夹住但发生相对滑动与提前脱落分开处理，不以完全无滑移作为全量数据生产的前提。具体释放方式必须与任务合同和执行器组合一致；原精确落点或直立任务仍按原目标验收。收集到区域内的任务可以使用不同的区域目标合同，但必须事先定义，不能事后改规则放行旧失败。
