# 从实测失败到可检验的生成流水线方法

日期：2026-10-20。本文独立审阅产物和代码，提出研究设计；本文审阅工作本身未训练、未提交付费请求，并同步记录同会话主执行流程新增的真实实验。除明确列为实测的结果外，实验数量、阈值和预期收益均为建议，不能作为已完成结果。

**当前最值得研究的对象是：在冻结的任务契约下，如何定位跨域生成过程中丢失或改变的任务信息，并用有限预算恢复这种信息。** 可先完成数据生成与验证方法的论文实验，不必以策略训练作为当前主线。单个失败视频足以暴露验收漏洞，不足以支持生成成功率、审核错误率或方法优越性的统计结论。

颜色记录中 frame 0/1 的红色质心仍在右碗，frame 2（0.0833 s）的候选面积骤减到 291 像素，frame 3（0.125 s）在左碗。frame 2 需要单独核验；不能把 HSV 候选位置当作苹果运动真值，更不能据此计算真实 3D 加速度。本文沿用“起始连续性破坏”的可见诊断，不宣称完成物理原因定位。

**额外协议问题：** 当前 [小试脚本](scripts/echoflow_pilot.py) 的 `BLIND_PROMPT` 列出 `objects` 等字段，却未列出 schema 必填的 `visible_discontinuities`；schema 规定关系为字符串列表，返回却是关系字典列表。该脚本确实通过 [provider](r2h_pipeline/providers.py) 请求 `responseJsonSchema`，但请求 metadata 未保存 schema 内容或 hash。应先统一提示与 schema 的单一来源，再分别测量中转协议遵循和视觉内容正确性。不能将现有结果完全归因于 Gemini 的原生结构化输出能力。

现有 `quality_rejection.json` 明确声明审核来源为 assistant visual inspection 加单场景颜色诊断，**不是独立人类 ground truth**。论文最终测试必须另外获得盲标与复核；当前记录适合作为开发用回归案例。

### 同日新增实测：显式逐帧观察已能发现问题

主执行流程对同一失败视频新增两次独立 Gemini 调用，均使用 8 张 960×960 图像、同一观察 prompt/schema、匿名输入，不告知目标；图像输入 token 均为 9856。结果均仅剥离一个外层 JSON 围栏并记录规范化，随后通过完整 schema 与所请求帧的覆盖检查。**这里的帧覆盖只指输入的 8 帧，不是全视频、全部事件或接触已验证。**

| 方法与结果 | 抽帧 | 实测观察 | 可支持的结论 |
|---|---|---|---|
| [均匀显式帧结果](/mnt/sdg/datasets/real_sim_human_pipeline/repair_study_20261020_v1/review-uniform/result.json) | `[0,27,55,82,110,137,165,192]` | 正确读出帧 0 在右碗，标记 0→27 的未解释位置改变，区间宽 1.125 s | 显式首帧及逐帧回答已能暴露矛盾；仅凭稀疏帧，不能证明两帧间绝无有效搬运 |
| [边界加密结果](/mnt/sdg/datasets/real_sim_human_pipeline/repair_study_20261020_v1/review-boundary/result.json) | `[0,1,3,6,24,72,144,192]` | 正确报告 1→3 帧之间右→左变化，且手仍未搬运；区间宽约 0.083 s | 本例中的疑点定位更窄，早期可见证据更直接；仍未观察 frame 2 |

因此不能写成“只有密集采样才发现错误”或“多尺度审核已提高检出率”。均匀显式输入也发现了异常；本例直接展示的是边界加密的定位收益。边界时间表是在已知失败之后选择，属于诊断性回放，不是预注册盲测。新的显式帧任务同时改变了输入形式和观察协议，因此与旧完整视频审核的差异也不能单独归因于采样。

本轮还完成一条 [固定角色/画面方向的生成对照](/mnt/sdg/datasets/real_sim_human_pipeline/repair_study_20261020_v1/submit-role-grounded/request_metadata.json)：复用原锚图及生成配置，仅追加“源=图像右、目标=图像左、角色只绑定一次”等文字。新视频已返回并全解码；助手直接查看及独立匿名帧审查均观察到右碗初态保持、右→左搬运及收手。原两项明显缺陷在新样未观察到，记录为任务语义候选通过，未正式发布进训练；见[新视频](/mnt/sdg/datasets/real_sim_human_pipeline/repair_study_20261020_v1/role_grounded.mp4)及[质量边界](/mnt/sdg/datasets/real_sim_human_pipeline/repair_study_20261020_v1/repair_quality_observation.json)。它仍是无固定seed的单例对照，不能归因或估计统计修复率。

## 2. 失败分类：同一视频可同时触发多项

记录“最早可确认违例区间”和“受到影响的后续要求”，允许多标签，不用一个笼统的 `generation_failed` 取代原因。

| ID | 失败层 | 当前状态 | 可操作检测与证据 |
|---|---|---|---|
| P1 | 传输、媒体、任务关联失败 | 发生过提交超时；视频已恢复，绑定仍有限制 | 请求 ID、输入/输出 hash、服务端任务回显；解码、PTS、首尾存在性独立检查 |
| P2 | 输出协议失败 | 已发现 | 原文 JSON parse、schema、枚举/范围、时间有效性分层报告；不以“去掉围栏”升级为内容正确 |
| A1 | 首帧编辑改变任务状态 | 待验证风险 | 源图与编辑图分别标实例/角色及关系，比较苹果所处容器、数量、容器可供性；像素相似仅辅助 |
| T1 | 锚帧到运动的起始连续性失败 | 已发现 | 保留真实帧 0；连续解码起始窗口；身份、可见性、位置及关系跳变共同取证 |
| R1 | 跨帧实例或角色重绑定 | 已发现其后果；内部原因未知 | `source` 只能在 t=0 绑定一次，之后不能解释为“当前占用的碗”；跨帧跟踪和关系证据检查 |
| G1 | 目标或对象选择错误 | 已发现 | 原 t=0 源/目标映射下的终态错误；不是按生成视频重新命名源碗后评分 |
| E1 | 必要事件缺失、顺序错误、伪接触 | 起始无搬运的关系改变已发现；其他类型待测 | 人工可见交互标签、关系状态转移、必要偏序；遮挡中接触记 unknown |
| I1 | 复制、消失、对象替换、干扰物移动 | 待验证风险 | 实例数、身份、遮挡进出及持久性；缺测不直接等价于消失 |
| J1 | 分段生成/修复的边界不连续 | 尚无分段修复实测 | 拼接前后对象、手、支撑/持握状态与运动方向；检查整个重合区 |
| V1 | 审核证据采样遗漏 | 原审核漏掉早期异常已发现；采样是否为原因待测 | 显式帧输入、独立帧 0 查询、带 PTS 窗口与完整视频对照 |
| V2 | 证据看得到但理解/绑定错误 | 待定位 | 同一组已知关键帧：单帧问答、成对比较、连续窗口、全片描述逐级对照 |
| D1 | 外观线索代替任务角色；泛化下降 | 待验证风险 | 保持目标更换外观，与保持外观更换角色的正交对照；未见人物/资产/视角测试 |
| L1 | 契约、谱系或配对泄漏 | 待验证风险 | 契约 hash、来源图、祖先分组划分；匿名评估不暴露 prompt、文件名、目标标签 |

`P2` 可以导致系统保守拒收，因此本次不能称作“坏视频已被审核通过”。准确说法是：**结构化审核不可用，且其可读语义报告存在假阴性；最终系统通过额外检查拒收了该片。**

## 3. 可冻结、可核验的任务等价 contract

定义 `C = (R, B0, I, G, E, P, F, A, U, S)`：

- `R`：抽象角色及实例约束，如被搬物、源容器、目标容器、干扰物；明确一对一或允许复用。
- `B0`：各域 t=0 的实例到角色绑定及证据，包括可见位置、框/掩膜、实例 ID、PTS；一经确认即冻结。
- `I/G`：初态与终态关系谓词；必要时含终态保持的观察窗口。
- `E/P`：必须事件与必要偏序；逐条说明比较事件开始、完成还是状态首次成立的时间。
- `F/A`：禁止变化与允许实现差异；只约束任务真正需要的部分。
- `U`：未知量、遮挡、歧义及其对不同数据用途的限制。
- `S`：来源、任务版本、源窗口、原生执行、生成分支与证据 hash。

对于苹果例子，源角色在首帧绑定为图像右碗，目标为图像左碗；角色定义仍是“最初装苹果/最初空的容器”，左右只是当前视图的实例定位证据。改变相机或跨域布局后允许映射变化，但不能在同一视频内重新绑定。两只碗都空或同样装苹果时，“唯一空碗”不可识别，应返回歧义并修任务规格，不能随机猜。

任务等价是对角色关系与必要事件的检查，不是强制两条视频有相同像素轨迹。建议分开输出三项资格：

| 资格 | 要证明的内容 | 本轮可否自动拥有 |
|---|---|---|
| `task_only` | 角色映射、完整任务窗口、目标、必要事件及偏序成立 | 必须独立验收；当前失败视频不合格 |
| `motion_correspondence` | 额外有可识别点/实例、相机映射、受锚点限制的单调时间对应 | 不可由“看起来相似”授予 |
| `dynamics_matched` | 机制和物理参数对应，有足够测量/控制依据 | 普通生成 RGB 不具备 |

每个谓词输出 `true/false/unknown` 与证据窗口；程序对冻结契约求值，VLM 只观察。关键项 `false` 为已知失败，关键项 `unknown` 为证据不足；两者分开统计，严格用途均不准入。若未知只涉及非必要抓法，则不应拒绝合法的 `task_only` 样本。

“抓取”在 RGB 中应写为可见的手物相对运动、脱离支撑与稳定持握等证据，而不是不可见接触力的真值。“收手”和“碗不动”是否必须，应由用户任务/源任务范围确定；本次生成请求已明确要求，因此可以检查。不要将全部机器人控制阶段强行变成人类语义全序；抓取建立与离开容器可能在时间上交叠。

**可测假设 H1：** 冻结角色绑定与必要谓词，能降低“动作像取放、实际目标错”的错误接收，同时保持允许抓法/速度变化的合法样本召回。对照只改变表示与比较器，固定视频和观察证据；否则无法知道改善来自 prompt、模型还是验收规则。

## 4. Ground truth 从哪里来

需要三套用途不同的证据，不把其中一套覆盖到另一套。

| 数据 | 标签来源与流程 | 有效范围 |
|---|---|---|
| 仿真原生 rollout | 冻结任务＋执行日志：实例 pose、关节、接触、渲染 mask/depth、相机、动作、PTS | 该仿真世界的 oracle；仍需验证坐标、单位、碰撞资产与成功谓词实现 |
| 真实/合成人类视频 | 两位独立标注者逐帧检查角色、可见关系、事件区间及 unknown；冲突经第三人或联合复核 | 可见语义与 2D 证据；不是隐藏接触力、真实质量或腕部 3D |
| 受控破坏样本 | 从已核验合法片段进行可记录的帧序/拼接/对象层变换，保存变换脚本与位置，再人工确认 | 已知注入错误及时间位置；不能估计自然生成失败分布 |

标注时先隐藏生成器、生成提示、方法组和审核器结论，让标注者记录实际发生的事情；之后独立的契约比较步骤读取目标。避免让标注者只回答“是否按 prompt 成功”而迎合意图。实例身份先锚定 t=0，之后允许 `occluded/uncertain/reidentified`，不要凭空填补轨迹。

事件时间用区间表示：最后一帧不成立与第一帧确定成立之间为边界不确定区间。模糊接触允许多个合理边界，不用 VLM 自报的 2.5 s 等小数当精确 GT。报告标注者一致率、关键关系分歧率、事件边界分歧分布和仲裁比例。

当前已知坏片必须进入开发/回归集，不能在看过它并调阈值后又作为唯一测试证明。最终测试按源会话、原生轨迹与所有派生后代分组；相同母视频的多个 corruption 不能跨开发与测试，也不能当独立样本计算过窄置信区间。

## 5. 多尺度审核：先解决证据覆盖，再判断语义

建议链路：

```text
媒体/PTS/首尾完整性
  → 全解码、冻结 t=0 实例角色
  → 固定全局时间覆盖＋强制边界窗口
  → 跟踪/分割提出异常窗口
  → 带真实 PTS 的连续邻帧复核
  → 盲读观察报告
  → 契约逐项比较与证据不足处理
```

对 8 秒、24 FPS 的开发片，可先明确检查首尾各 0.5 秒的全部帧及全局稀疏帧；异常窗口用原始帧率展开。时间窗口是待校准设计，不是适用于所有速度与时长的固定定理。高速操作、长遮挡和长任务必须按事件尺度及预算调整。

跟踪器只负责提议疑点，不作最终真值。疑点包括可见对象位置/面积突变、实例数变化、角色关系变化而缺少可见转移过程、遮挡后身份不确定、终态未稳定。将相机运动、遮挡、镜面/颜色变化作为正常困难负例；速度大不能直接判物理不可能。HSV 只能保留为本场景回归基线。

### 5.1 审核采样的受控对照

固定审核模型版本、prompt/schema、图像分辨率、视频与总图像输入预算，比较：

| 组 | 审核证据 | 要回答的问题 |
|---|---|---|
| V0 | 原始完整视频输入 | 当前实际服务表现；内部抽帧未知，单独记录 |
| V1 | 显式均匀采样 K 帧，含真实首尾 | 可控采样的基础表现 |
| V2 | 同 K 帧，部分预算换成首尾密集窗口 | 边界覆盖本身是否有效 |
| V3 | 同 K 帧，边界＋全局＋异常提议的密集窗口 | 自适应分配是否超过固定方案 |
| V4 | 同 K 帧，人工已知错误位置指导采样 | 仅作 oracle 上界；不作为可部署方法 |

例如 K=64 可分配约 26 帧给首尾各 0.5 秒、16 帧给全局、剩余预算给异常窗口；实际去重、重叠和重复展示均记账。不满足预算时先按预注册规则分配，不能在看到答案后加帧。低成本跟踪可扫描全部帧，但需另报计算量；不是“同样的总计算”。

V0 的服务端采样不可控，不能声称与 V1–V3 完全同视觉 token；V1–V3 才是采样策略的主要因果对照。另做相同信息、不同包装的实验：逐帧序列与 contact sheet 使用相同可见分辨率/帧数，避免缩略图变小造成伪结论。

测试错误在首/中/尾出现、持续 1/2/3/6 帧、事件前后以及遮挡期间的检测。真实异常和注入异常分表报告；只对注入错误很敏感，不能证明能发现自然生成错误。

### 5.2 将“未看到”和“看错了”分开

对现有片段可按如下问题逐级定位，未来需要新模型调用时再执行：

1. 仅给真实帧 0，询问苹果所在实例；不提目标。
2. 给帧 0 与帧 3，询问对象/容器关系是否改变。
3. 给 0–0.5 秒连续帧，询问是否存在可见搬运证据。
4. 给相同关键证据加后续全片，检查是否被长段概括覆盖。
5. 对原视频添加无内容改变的播放时间伸展或显式前缀展示，比较审核变化；这只诊断时间采样敏感性，不计入生成修复。

若第 1 步即错，是空间/对象识别问题；前 3 步正确而第 4 步错，支持上下文或摘要干扰；仅完整视频错而显式帧正确，支持输入/采样链路是候选原因。以上仍不能反推出专有模型内部机制。

**可测假设 H2：** 相同可见帧预算下，多尺度方案提高短时关键违例召回及定位精度，并维持合法样本召回。新增单例仅支持继续检验定位精度，尚未证明召回提升。若只提升拒收率而错误接受未下降、合法样本大量被拒，应判假设未获支持。

## 6. 事件锚点生成：测“约束了什么”，不把锚点当连续性保证

按任务构造锚点：完整初态、抓取后离开源支撑、到达目标但未释放、释放后稳定终态。锚点来自仿真原生事件状态；若转换为人类图，每张仍需角色/关系审核，不能独立生成后直接认定彼此兼容。人类合法抓法可以不同，不必将机器人每个停顿变成锚点。

分清三种条件强度：

| 方法 | 当前含义 | 能声称的控制 |
|---|---|---|
| 文本列出事件与角色 | 当前 first-frame API 可表达的语义要求 | 软条件；原 prompt 已包含完整抓取/搬运/释放，失败不能简单解释为缺少步骤文字 |
| 多个图像/视频锚点条件 | 仅在后端真正支持时使用 | 锚点输入可控，输出是否遵循仍须验证 |
| mask/depth/轨迹及重建约束 | 独立受控编辑或几何路线 | 条件更丰富；重建/渲染约束不能自动变成生成 RGB 的准确 3D GT |

生成对照 G0–G3 必须固定同一角色契约、源 rollout、生成后端、调用预算与最终独立评估：

- G0：普通任务文字＋首帧。
- G1：显式角色、初终态、必要事件及允许变化＋首帧。
- G2：G1＋事件锚点；只在同后端确实支持时视为单因素消融。
- G3：G2＋验证后定向修复。

若 G2 必须更换后端，则它是“另一条生成路线”的系统对照，不能把差异全部归于锚点。还应比较等数量均匀时间锚点与事件锚点，隔离“锚点更多”与“事件位置选择”。

锚点间仍可能发生瞬移、复制、错误接触、先达目标又退回。评价必须在整个连续片段执行，不能只验锚点。报告锚点前后违例率、所有间隔的完整事件率和总有效产率。一个没有中间动作、仅靠跳变满足所有锚点的片段必须失败。

**可测假设 H3：** 相同条件数量和预算下，事件锚点比均匀锚点减少跨阶段角色/结果漂移；若只保证终帧、增加接缝错误，则不支持完整任务保持。

## 7. 定位后修复：失败时间短，不等于可局部修复

修复单应包含：契约违例 ID、证据窗口、当前/所需状态、受影响角色、冻结区域、后续依赖、可用后端能力、最大预算。修复器不能改原契约、移动原始 t=0、删除失败分母或改名目标。

| 故障 | 合理修复范围 | 为什么 |
|---|---|---|
| JSON 围栏/字段不一致 | 结构化协议层 | 去围栏可另存诊断，但不得发明缺失观察；内容需独立验收 |
| 局部纹理/手指伪影，任务状态和后续事件正确 | 可尝试局部视频编辑 | 修复上下文有限，但仍要检查对象身份与修复外变化 |
| 短时位置跳变，前后正确状态一致且后续仍符合契约 | 可尝试带前后状态的局部重生成 | 需要验证时间、手物状态和速度衔接 |
| 本次起始跳变后，人手从错误源碗向错误目标搬运 | 至少重做受影响的后续动作，通常重生成整任务窗口 | 修好 0–0.125 秒后，其余动作仍以左碗为源，不能保留错误后缀 |
| 角色不清/目标映射不明 | 先修任务/锚点绑定，再生成 | 不是视频润色能修复的输入歧义 |
| 接触过程持续不可见、不同工具互相冲突 | 调整视角/条件或降低用途等级 | 无证据不能靠“更自信的审核”补成真值 |

局部修复的前提是“失败的后续影响局限”，并非“异常帧数少”。可按事件依赖图找修复后缀：改变的状态会影响哪些后续事件，就把这些事件纳入修复或重新验证。

比较 `R0=无修复直接拒收`、`R1=相同预算重新生成整片`、`R2=知道失败类别的整片重生成`、`R3=类别＋时间定位＋受控局部编辑`。R2 能分离“有错误反馈”与“局部编辑”本身的作用；R3 若后端不支持，应明确记不可用，不用剪辑冒充。提供 GT 定位的修复只作为 oracle 上界。

修后重新跑完整验收，并由不知道方法组的标注者复核。主要指标为“每个原始失败在总预算内最终变成独立合格片的比例”，同时报告新违例率、原正确区域的改变、接缝失败、费用和延迟。不能只报告已被系统接受的修复片有多少看起来成功。

**可测假设 H4：** 对可局部修复类别，定位修复在同成本下比整片重生成增加有效片；对全局语义漂移不一定占优。按类别报告，而不是将所有失败混成一个平均收益。

## 8. Role identity、分支信息与 domain generalization

这三项不能互相代替：

1. **跨域角色保持**：不同布局/外观中，哪个物体对应任务中的被操作物、源与目标。
2. **同初态目标可辨别**：视频是否保留两个互斥合法目标的差异。
3. **域外可用性**：生成/审核方法在未见外观、人物、相机、资产或机制上仍有效。

当前“两碗、一个苹果、唯一空碗”的场景只有一个规定目标，**不能单独测试同初态分支信息保持**。应增加两个合法目的地，或两个可选被操作对象，并对所有分支复用相同、目标无关的初始人类图。

建议一个最小正交测试：

| 改变 | 固定 | 期望不变/改变 |
|---|---|---|
| 左右位置、相机、颜色、人物、背景 | 同一角色任务 | 契约等价和目标盲读结果不变 |
| 被操作对象或目标容器角色 | 尽量相同外观与同一初态 | 完整视频应导致不同目标判断 |
| 同一任务的速度、手别、合法抓法 | 角色与结果 | 应保持合法，不能过度拒收 |
| 必须的过程顺序 | 相同起终态 | 完整时序应可区分；首尾应不足以区分 |

按人物、背景、目标和生成后端交叉分配，避免某个人物或模型水印只对应一个目标。对称布局尤其需要稳定实例证据；禁止根据生成后终态反向决定哪个容器原本叫目标。

先由人工盲读完成目标恢复，作为视频本身的可辨别性标签；再比较固定 VLM/工具的识别结果。否则 VLM 自己生成、自己评审可能共享同一错误。分支组全部目标都正确才算完整组成功，另报各目标覆盖率和混淆矩阵，防止只保留容易目标。

域外测试至少拆为：新外观但同关系、新几何/可供性、新人物/视角、新机制，以及真实人类视频上的审核表现。仿真原生 oracle 可以衡量对象角色/事件提取器在 render 上的正确性，但不能代表合成人类或真实视频上的表现。

**可测假设 H5：** 角色条件与整组验证减少目标坍缩，且收益在未见外观上保持。这里可先测数据、生成器和审核器泛化；尚无策略训练/真机实验时，不能将结果命名为“机器人域泛化成功”。

## 9. 指标、预算与实验单位

使用人工复核的最终标签 `valid/invalid/ambiguous`；歧义片单列，不任意算对或算错。不同用途资格分别统计。

| 指标 | 定义/分母 | 防止的误读 |
|---|---|---|
| 原始有效产率 | 独立判定 valid 的初次生成 / 所有初次请求 | 审核放宽不会提高该指标；超时/缺片保留分母并另报 |
| 准入有效产率 | 被准入且独立 valid / 全部生成请求 | 将生成能力和准入保守度一起反映 |
| 无效片误接收率 | 被准入的 invalid / 全部独立 invalid | 衡量漏检；不与“接受集污染率”混用 |
| 接受集污染率 | 被准入的 invalid / 全部被准入 | 接受数为 0 时为未定义，不能报 0% 污染且声称方法好 |
| 合法片召回 | 被准入的 valid / 全部独立 valid | 防止全拒收解法 |
| 协议有效率 | parse、schema、语义字段有效分别统计 / 全部审核调用 | 输出 JSON 与看懂视频分开 |
| 违例召回与定位 | 按类别，短时/边界分层；区间 IoU、边界误差、到最近 GT 区间距离 | 对瞬时事件用邻帧容忍度，避免零长度 IoU；先固定匹配规则 |
| 事件/角色正确率 | 必要事件召回、偏序准确、t=0 角色绑定准确、跨帧身份切换数 | 不用平均分掩盖关键事件缺失 |
| 分支完整率 | 组内所有目标正确且可盲读区分的组数 / 所有组 | 单条视频漂亮不保证任务信息仍完整 |
| 修复收益 | 预算内修复为 valid 的原失败 / 所有进入修复试验的原失败 | 连失败的修复请求和超时都计入 |
| 成本 | 生成＋审核＋失败重试＋修复的实际货币、推理资源、人工分钟、墙钟延迟 | 分别报告费用；未知收费写 unknown，token 不等于金额 |

主要实验单位为独立源任务/初态组，而非每一帧。多次生成重复测随机性，但不能把相同源的大量后代当完全独立样本；报告按源组 bootstrap 的置信区间和分任务结果。配对消融尽量用同源条件；闭源后端若无可靠 seed，随机化请求顺序、分时块交叉运行并记录 model/version，不能声称严格复用相同随机数。

等预算同时给两条曲线更有说服力：固定请求次数下的有效产率，以及固定总实际成本下的有效产率。图像锚点、审核窗口和修复都算成本。失败类型分布随筛选改变，需要报告筛选前后覆盖，避免只剩容易、无遮挡、慢动作样本。

## 10. 最小执行次序：先无付费证据闭环，再小规模对照

本节是后续建议，不表示已启动。

**阶段 A：现有产物离线闭环。**

- 将本次原始视频、逐帧 PTS、请求/响应、契约和拒收结果锁定为回归案例；校验是否引用同一媒体 hash。
- 完成提示/schema 单一来源检查；分别用现有合法/非法响应验证解析、schema 与内容门控，保留围栏响应为失败样例。
- 确认 t=0 角色不能重绑定，unknown 不会自动变成 true；测试目标反转、缺事件、乱时间、缺实例、歧义映射。
- 补起始 frame 0–6 的人工逐帧核验及首个异常区间；当前不能用 2 FPS 接触表证明亚秒级接触完整。
- 先列出已有人类合法片与原生仿真成功片，确认可构成开发正例；只有一个坏例无法校准误拒率。

**阶段 B：审核器与规则的离线基准。**

可先从 12 个独立且完整的合法源片开发，按源组分开发/留出，制作短时跳变、终态错误、错对象、遮挡重现、合法速度/手别变化等对照；这是开发规模，不能支撑强泛化结论。人工完整标注优先覆盖所有关键谓词和异常窗口。已有工具可离线运行；需要新 VLM 调用的部分另列预算再执行。

**阶段 C：生成路线小实验。**

预注册 3 个机制族 × 4 个初态组 × 2 个合法目标，共 24 个任务条件；每条件各方法至少 2 次生成只是探索规模，不能据此声称稳健统计胜出。先确定各路线实际支持的条件接口，再冻结契约与 blind test。只有 H1/H2 的审核校准可用后，才有理由用新生成测试 H3/H4/H5；否则只是用不可靠的标尺挑视频。

**阶段 D：留出验证和扩量决策。**

在未参与 prompt/阈值选择的新任务源、资产与人物上复核。依据误接收、合法片召回、有效片成本与分支覆盖决定扩量；不因一个视频修好或软件单测通过就开始上千条生成。后续训练只是验证数据对策略的效用，属于后续独立证据层。

## 11. 近似工作与可成立的论文主张

下面是本轮核验的一手来源；“我们应如何定位”是基于它们的研究判断，不是已证明的创新性结论。

| 已有工作 | 已经覆盖的思想 | 本项目不能照此宣称首创 |
|---|---|---|
| [Zero-WAM / HumanGen](https://arxiv.org/html/2608.26103v2#S2.SS2)，2026 | 机器人轨迹分析、Nano 等首帧人类化、视频生成、VLM 检查；保持语义同时变化布局/视角 | 机器人视频转人类视频＋VLM 筛选；外观多样化与任务语义分离 |
| [SimFoundry](https://arxiv.org/abs/2606.28276)，2026 | 视频到可交互仿真、对象/场景/任务变体 | real-to-sim 自动构景、扩量、digital cousins |
| [NeSyCR](https://arxiv.org/abs/2603.18495)，2026 | 符号过程、跨域不兼容检查与程序修复 | 将视频转事件/逻辑程序、检查依赖并修复的一般思想 |
| [TempCompass](https://arxiv.org/abs/2403.00476)，2024 | 静态内容相同但时序因素不同的冲突视频、多种问答形式评估 | 用反事实视频或打乱顺序测试时序理解 |
| [VBench](https://arxiv.org/abs/2311.17982)，2023/2024；[VBench-2.0](https://arxiv.org/abs/2503.21755)，2025 | 视频质量分维度，物理/常识等内在可信性，generalist 与 specialist 结合 | 把外观、时间、物理分开评分；VLM 联合专用检测器 |
| [VACE 官方实现](https://github.com/ali-vilab/VACE)，ICCV 2025 | 文本、视频、mask、参考图条件及视频编辑 | 受 mask 控制的视频局部编辑；它也不自动给出机器人任务正确性证明 |
| [KinoGen](https://arxiv.org/abs/2610.20552)，2026-10-14 | 渲染机器人/物体状态，编辑关键帧后再生成周围运动，并在重建中强制满足目标状态 | 关键帧控制、编辑后再生成、生成与几何约束闭环。其对象是机器人运动参考，不能直接当成人类任务视频方法 |

特别是 KinoGen 已明确提出关键帧修改后重生成，且报告终点满足与中间穿透需要分开测。因此，不能把“事件锚点＋局部修复”这几个词本身包装成新颖性。

目前较合理、可被实验推翻的候选主张是：

> 给定跨域等价的角色/事件契约与有限生成预算，显式保存初态角色、分配关键时间证据、定位违例影响范围并按范围修复，能在独立盲标下提高完整任务视频及多目标组的有效产率，并降低错误准入；收益在未见外观和任务源上仍可观察。

该主张需要 H1–H5 分别支撑。若结果只表明“多花预算让 VLM 看更多帧”或“换更强视频模型会更好”，应收缩为工程评估结论；若局部修复不优于等预算重生成，保留失败结果并修改方法。当前贡献可落在**任务契约约束下的生成—验证—修复算法、可复用失败基准和有独立标签的预算曲线**，不需要提前声称新策略架构、物理真值恢复或真实机器人泛化已完成。
