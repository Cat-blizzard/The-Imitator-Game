# 状态条件与事件纠错：受限调用预算的 A/B 对照

本文件说明已实现的可执行协议，不预先报告效果。入口为 `scripts/run_controlled_20261020e.py`，实现为 `r2h_pipeline/controlled_experiment.py`。截至准备完成，仅离线构造请求和运行测试；本文不把准备状态写成已经生成了六条视频。

## 比较什么

首轮固定三个来源：苹果从碗中搬到另一个碗、合上的书放入打开的箱子、只打开右柜门。每源 A/B 各一条，共六条初始候选。两组使用完全相同的既有人类首图、完整任务提示、必要步骤、不变量和可见手数量方案。

| 部分 | A：首图与任务文本 | B：状态条件与定向纠错 |
|---|---|---|
| 初轮视频条件 | 共用人类首图＋完整任务提示 | 完全相同首图与提示＋人类终图 |
| 终图来源 | 无 | 仿真终态为几何依据，共用人类首图为外观参考，Nano 多图编辑 |
| 初轮审核 | 同 24 帧规则、同 VLM 提示、同任务与人物方案、同仿真首终态证据 | 同左 |
| 初轮失败或未知后 | 原条件再抽样一次 | 将已观察问题追加为修复约束；必要时重新编辑终图 |
| 修复轮审核 | 同一任务审核提示、均匀与边界 24 帧 | 同一提示、仍 24 帧，但可把部分采样移向前次问题窗口 |

A 的提示不故意省略关键步骤；B 初轮只是增加终图条件，并承担构造终图的费用。因此初轮比较的是**条件构造管线**，不能隔离为“某一句提示词的因果贡献”。修复轮可同时改变条件、文本与检查位置，也不能归因于某一个组件。初轮结果和修复后结果必须分列，原始失败不得被修复结果覆盖。

三个来源都绑定了真实人类视频及时间窗口、机器人视频、轨迹、仿真首终图、旧任务记录的路径和 SHA256。这里复用的是历史来源，不重新证明它们通过本轮严格规划器。这个对照不检验新增家居资产、严格碰撞规划或整条 real→sim→real 管线的因果效果。柜门两组共用的是已经修过的单手首图，避免把一组输入旧三手图当作公平对照。

## 预算和停止条件

每个来源、每组最多 **图像编辑 2 次／视频生成 2 次／VLM 审核 2 次**，视频请求都为 8 秒、720p、`ratio=adaptive`、不生成音频。这是相同调用上限，**不是相同实际支出，更不是已核对人民币账单**。

- B 初轮构造终图通常用 1 次新图像调用；A 初轮可以是 0 次。
- 历史共用首图是已发生的共同成本，记录来源，不称作免费可复现。
- 每个已经开始的付费调用都占预算，包括超时而提交结果未知的调用。
- 记录返回用量、耗时与任务 ID；未取得账单时货币成本写未知。
- 初轮七项检查均在采样范围内有支持时停止，不为了凑满预算额外生成。
- 失败或未知可以开启第二次；最多两次，不能不断生成到出现想要的成功。
- 未知 POST 不重发，也不能通过换目录或增加版本跳过。任务已知失败、取消或过期则停止；GET 返回未知状态则阻断，保留原任务调查。

为保留每组两次视频审核的机会，本协议没有额外收费的终图语义预审，图像输出先做本地解码。终图错误会在统一视频审核中记录；不要把它描述为“所有输入锚图已审核通过”。完整生产管线可以另设图像预审预算，但不临时加进当前对照。

## 审核究竟判断什么

每项单独返回 `yes/no/unknown`、实际帧号、对应 PTS 和可见依据，不输出综合平均分：

1. 初始任务状态；
2. 放手或撤手后的目标状态；
3. 必要事件顺序；
4. 必须保留的物体及显露内容；
5. 声明的人物／可见手方案；
6. 接近、操纵、放手过程的可解释性；
7. 可见物体连续性。

两组审核都看到同样的仿真首终图。对于柜内物体，这提供了首帧不可见内容的来源依据；不能只凭视频“看着清楚”就断言物体保留。审核图像中的来源图有明确静态标签，不当成候选视频发生过的帧。

审核请求不包含组名、历史通过与否或方法身份。`actor_plan` 要说明至少能看见几只手；不能把多出的手随意解释成另一个参与者而忽略声明方案。只有提供过的帧号和准确时间可被引用；伪造帧、时间错位或明确结论无证据都拒绝解析。24 帧只能支持局部可见事实，不能证明整段无瞬移、真实接触力或物理真实性。

B 修复轮沿用前次问题区间作注意力提示，但新视频可能重新安排时序，旧帧号不是新视频事件真值。所有结果保持 `quality_release_approved=false`、`training_admitted=false`，独立密集审核与仿真准入仍是后续步骤。

## API 生效验证

请求使用原生 `first_frame`／`last_frame` 字段，而不是把两张图拼成一张。离线校验确认不混用首尾模式与参考模式。官方要求 Seedance 2.5 首帧／首尾模式采用 `ratio=adaptive`。[官方 2.5 指南](https://docs.volcengine.com/docs/ark/seedance-2-5?lang=zh)

每个成功生成目录保存 `media.json` 和 `api_effect_validation.json`，记录请求别名及参数、真实宽高／帧数／FPS／时长、后端原始响应及其返回的参数。720p 是预设档位：例如方形输入对应 **960×960**，不能按“短边必须是 720”判定失败。代码按官方表对常见比例校验，非表内自适应比例保留未知。[官方尺寸表](https://docs.volcengine.com/docs/ark/seedance-2-5?lang=zh)

本轮**不指定 seed**。创建接口文档的 seed 小节仅明确列出 1.0 两款，而 2.5 的 Draft 章节又出现 seed；当前中转的 2.5 种子控制尚未验证。记录后端返回 seed，但不宣称 A/B 使用同一随机噪声。将来若端点明确支持，可在新协议中同源设置相同 seed，仍不能保证不同输入条件获得匹配的随机生成过程。[创建参数](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh&redirect=1)、[查询返回字段](https://docs.volcengine.com/docs/ark/get-video-generation-task-api?lang=zh)

请求被接受和 raster 大小一致都不能独立证明中转实际使用了所声明的模型权重，也不能证明每张条件图都发挥作用。后端模型标识与输出内容证据分别记录。

## 执行方法

在 `/mnt/sdf/dataset/zhouxunzhe/zhiqi` 下运行。下列 `plan` 不联网；`advance --execute` 每次最多完成一个付费步骤，或一次已有任务 GET，不含隐式付费循环。

```bash
PolicyGen/.venv/bin/python data_generation_methods/scripts/run_controlled_20261020e.py prepare \
  --root /mnt/sdg/datasets/real_sim_human_pipeline/controlled_20261020e

PolicyGen/.venv/bin/python data_generation_methods/scripts/run_controlled_20261020e.py plan \
  --root /mnt/sdg/datasets/real_sim_human_pipeline/controlled_20261020e --case apple --arm A

PolicyGen/.venv/bin/python data_generation_methods/scripts/run_controlled_20261020e.py advance \
  --root /mnt/sdg/datasets/real_sim_human_pipeline/controlled_20261020e --case apple --arm A --execute
```

再次运行同一 `advance` 将推进下一步或读取缓存。A 顺序为提交→GET→审核，B 多一个终图编辑步骤。六条初轮全部完成后汇总，再根据协议决定第二轮；第二轮明确加 `--attempt 2`。不得把提交成功当成视频已经完成。每组有文件锁，防止同组并发越过预算检查；不同组可并行。

```bash
PolicyGen/.venv/bin/python data_generation_methods/scripts/run_controlled_20261020e.py summary \
  --root /mnt/sdg/datasets/real_sim_human_pipeline/controlled_20261020e
```

更换来源时先 `export-sources --sources /new/path.json`，由主执行器替换并核验绑定，再用 `prepare --sources /new/path.json --root /new/root`。已保存协议不可覆盖。当前根目录在本次源码最后完善前已 prepare，保持其既有内容；未指定 seed 的事实在请求和汇总中显式记录。

## 当前验证与工程边界

15 项针对性测试通过，覆盖相同首图与文本、原生请求、零调用准备、预算、未知提交、已知任务只 GET、失败/过期/取消/未知停止、初轮与修复分离、24 帧约束、伪造时间拒绝、方形 720p 尺寸及未指定 seed。测试没有付费调用模型，不等于新的视频已经完成。

几个值得单独继续验证的工程方向：

| 失败类型 | 当前实现 | 下一步需要的实际能力 |
|---|---|---|
| 隐藏内容丢失 | 终态条件＋共同来源图审核 | 增加首次显露区间，连续检查“逐渐露出”而不是最后突然出现 |
| 多手／人物方案偏移 | 输入声明预算，统一审核显式计数 | 接现有 MediaPipe／VLM 证据融合，冲突转局部密集检查，不能只相信评分 |
| 中间接触不连续 | 事件顺序与交互可见性，定向重生成 | 连续交互窗口、手物共运动与遮挡身份证据；首尾条件不能约束整段接触 |
| 长任务 | 当前仅固定 8 秒任务 | 按语义阶段分段、共享边界、跨段身份和状态审核；单独固定预算实验 |
| 改机器人时破坏物体 | 当前全图生成 | 显式保护区域的视频编辑分支，保持同任务并另做模型与费用对照 |

VACE 的官方工具接受视频、mask 与参考图，可作为局部编辑对照；这不是当前 Seedance 首尾 API 已经具备的 mask 控制，也不保证遮罩外毫无变化。[VACE 官方实现](https://github.com/ali-vilab/VACE)

这个六条初轮小样适合定位故障、验证请求和核算成本，不足以宣称总体成功率提升。后续应增加来源数量、独立重复和人工校验的坏例，并报告首次有效率、未知率、修复后新增有效率、修复破坏率及每条有效配对的实际成本。
