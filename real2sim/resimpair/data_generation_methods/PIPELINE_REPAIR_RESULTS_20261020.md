# Real → Sim → 合成人类参考：问题、修复与实测

更新：2026-10-20。当前研究对象是**数据管线本身**，没有启动模型训练。

## 1. 本轮要解决什么

不是把模型API接通就算完成。输入真实任务，扩充成仿真执行，再生成合成人类参考时，输出必须仍然表达原任务。每个阶段都应有能检查的中间产物、失败证据和对应修复动作。

本轮沿用一个已绑定真实人类窗口的任务：把红苹果从初始有苹果的碗移到初始空碗。允许布局、外观、本体不同；对象角色和任务结果不随生成结果改变。实际源、任务契约、原始失败均有文件哈希。

当前小试使用 Gemini、Nano Banana 和 Seedance，借鉴 Zero-WAM 的任务分析→编辑初图→生成人类视频→审核流程。**这是同类流程的本地变体，不是 Zero-WAM 官方管线的完整复现，也不能据此认定其发布数据具有本例错误。** 其论文第2.2节采用的具体后端还包括Wan/Kling。[Zero-WAM](https://arxiv.org/html/2608.26103v1#S2.SS2)

## 2. 已经实测的问题与修复

| 问题 | 本地实际证据 | 已做修复或正在验证 | 当前结论 |
|---|---|---|---|
| 首态连续性破坏 | 第0帧红苹果在画面右碗，第3帧0.125秒已在左碗，手仍未接近 | 密集边界证据；固定来源/目标角色的生成对照 | 原视频拒收，不能删除开头后声称原任务被保持 |
| 搬运方向/最终目标改变 | 随后手把苹果从左搬到右，结尾回到原source | 原角色在生成前冻结；新增明确画面左右与角色的prompt | 新视频已返回，本例从右碗搬到左碗、放下并收手；不是统计成功率 |
| 全视频概括漏掉最早变化 | 先前Gemini原文把初态写成左碗，未指出起始跳变 | 改为显式逐帧输入、时间戳、逐帧对象观察，再描述疑点 | 两次新审查均发现疑点，详见下一节 |
| 请求/响应结构不可靠 | 旧prompt与schema字段并非完全一致；响应有围栏并缺字段/类型不符 | prompt从同一schema构造；本地schema验证；只允许记录在案的单个外层围栏归一化 | 两次新响应都通过schema和帧覆盖检查；没有补写模型未返回的内容 |
| API超时但任务可能已提交 | 首轮180秒POST超时，之后只读恢复到视频 | 持久化调用前标记、记录请求哈希、禁止盲目重POST、只读查询 | 原小试没有重复视频提交；新对照单独记账 |
| 颜色跟踪可能误认皮肤 | 旧HSV诊断第2帧把手部红色碎片当目标 | 新探针绑定初帧ROI，加外观/面积检查，缺失保持unknown | 已处理193帧、127帧有外观候选、66帧unknown；提出1个位移疑点，不认证接触或物理 |

初帧编辑引起几何漂移、长程漏步骤、遮挡处穿透、不同目标被生成成同一动作等也需要测，但**本轮不能把尚未观察到的问题写成已发生的实验事实**。

## 3. 已完成的审查对照

两种新设置使用同一个坏视频、相同Gemini模型、相同提示和schema、各8张960×960图，不向审查者提供期望目标。时间来自实际视频PTS。VLM原响应、图片及hash均保留。

| 审查输入 | 是否描述首态为右碗 | 是否指出异常 | 定位区间 | 其他 |
|---|---|---|---|---|
| 原先整段视频概括 | 否，写为左碗 | 未指出起始跳变 | 无 | 格式/schema亦未通过；不是可用审核结果 |
| 显式均匀8帧，包含首尾 | 是 | 是，描述未解释的状态变化 | 第0–27帧，0–1.125秒 | 18.845秒；图像输入9856 tokens |
| 显式8帧，加密已知异常边界 | 是 | 是，描述手未移动时苹果换碗 | 第1–3帧，0.041667–0.125秒 | 19.632秒；图像输入9856 tokens |

新两组均需去掉一个外层JSON围栏，分别记录 `normalization=outer_json_fence`，内部内容未经修改，均通过严格schema与8帧覆盖检查。

另在本地重新解析旧原响应：即使去掉围栏，仍被严格验证器以 `review_schema_violation` 拒绝，没有靠放宽格式要求把旧错误记录转成成功。

**能得出的结论：** 本例中显式保留首态并逐帧观察已能找出疑点；密集边界采样让时间定位更精确。均匀采样也发现了问题，不能写成“只有我们的方法能检出”。

**不能得出的结论：** 这不是多任务检测率，也不是视频的物理正确率。边界帧是在已知异常后选的，不是盲测；均匀组中1.125秒未观察区间本身不能证明没有正常搬运。后续必须用独立未见视频验证自动窗口选择。

两次新审查都属于观察报告，没有把VLM输出升级为人工真值，没有让坏视频通过准入。

独立密集探针也定位到第1–3帧之间的可疑位移。助手直接查看图像发现第2帧两碗出现半透明红色影像，不能用旧颜色质心连成真实轨迹；此观察不是独立人工标注。探针保留unknown，导出逐帧候选、理由、137张无损检查帧和接触片。它适合这次单红色目标、近似固定相机的诊断，通用分割/跟踪尚未接入。

随后补上固定预算抽帧：根据探针事件记录自动选择首尾、最高优先位移两端及中间unknown，再按时间间隔补全局覆盖。预算8帧的实际结果是 `[0,1,2,3,50,97,144,192]`，没有硬编码第1、3帧。每帧都有选择理由，另明确列出4个unknown区间证据尚不完整。这一自动选择包尚未发给VLM，不能把它和上面已实测的手选边界8帧混为一组，也不宣称它已通过独立盲测。

## 4. 生成修复对照

现有baseline的图像锚点、视频模型、8秒时长、720p请求、adaptive比例和无音频设置保持。新请求只追加：

1. 来源碗＝首图画面右侧、初始装有红苹果的碗；目标碗＝画面左侧、初始为空的碗。
2. 左右以观察者画面为准，角色全程不变。
3. 手抓住前苹果留在来源碗；之后右→左；最终右空、左有苹果。
4. 绿色干扰物不动。

这是一个定位“角色/方向约束是否可能有用”的小样，不是充分统计消融。baseline没有固定seed，视频生成存在随机性。即使新样成功，也需要随机种子/布局重复和不含方向补充的重抽对照，才能归因。

当前请求记录：`repair_study_20261020_v1/submit-role-grounded/`。207.09秒后从POST正式响应取得任务ID，已确认请求关联。随后只读监控成功下载8.042秒、24FPS、193帧、960×960视频并完成全解码，监控已正常结束，没有重复POST。

**实际修复结果：** 助手查看首段密集帧及16帧全片接触表，新视频保持右碗初态，手伸到右碗抓取、抬起苹果，移到左碗放下，最后手离开、苹果留在左碗。原先的起始跨碗跳变和错误终态在新样中未观察到。

| 同一场景的诊断 | 原始样本 | 固定角色prompt样本 |
|---|---|---|
| 初始苹果位置 | 右碗，随后在手靠近前跳至左碗 | 右碗，接近/抓取前保持 |
| 实际可见搬运 | 左→右 | 右→左 |
| 最终容器 | 原来的source，违反原目标 | 原来的target，符合原目标 |
| 专用颜色探针位移疑点 | 1个 | 0个 |
| 专用探针unknown帧 | 66/193 | 0/193 |
| 核心任务观察结论 | 拒收 | 任务语义候选通过，待独立发布审核 |

探针0疑点、0 unknown不是物理正确证明；颜色身份仍可能误判。新增一次匿名Gemini帧审查也报告“右碗→手接触→左碗→收手”，通过schema和所选8帧覆盖检查，耗时25.249秒。该VLM没有报告疑点，不等于所有未输入的中间帧都被验证。

本例说明角色约束值得重复测试，**尚不能证明改善因果地来自prompt**，也不能写“修复成功率100%”。质量记录明确为 `core_task_semantics_candidate_pass_requires_independent_release_review`；未建立3D/力/接触真值，没有正式发布进训练。

本轮新增收费请求共1次Seedance生成、3次Gemini帧审查，没有新Nano调用；tokens保留但没有据此推算实际金额。原始失败和每次请求都保留。

针对这次单例使用左右描述，只是将角色映射到当前锚图的具体实现。**通用任务不能硬编码“从右到左”**；每次布局变化后，应重新绑定对象身份/ROI与source、target角色，任务层仍然是“从occupied到empty”。

## 5. 管线应形成什么方法

```text
真实视频窗口
  → 有来源的任务定义：对象角色／初态／必要事件／最终结果
  → 仿真资产与布局扩充，检查可达性、可供性和真实执行
  → 导出原生状态、动作、接触与可见性证据
  → 人类外观锚点，检查任务角色是否仍成立
  → 视频候选
  → 全局语义 + 首尾状态 + 异常时间窗检查
  → 错误归因：锚点／角色／事件／连续性／接口
  → 对应模块修复；不改原验收条件
  → 重新检查完整候选，保存失败与调用成本
  → 有资格范围的参考—机器人配对
```

当前已实现的是其中部分组件与这一小样的调用链，**不是全部环节已经自动完成**。原生depth/mask接入、通用视觉跟踪、事件级视频局部修复和生产配对导出仍需贯通。

三个值得检验的方法主张：

- **任务约束贯穿各域。** 不是只在最后问“像不像在拿苹果”，而是检查同一对象从哪个角色位置出发、经过哪些必要交互、达到什么状态。允许自然人手运动，不强迫复制机器人每一步。
- **按缺失证据分配审查资源。** 全局了解动作，再给身份不确定、接触转换、短时跳变、首尾边界更多观察预算。VLM解释可见证据，独立视觉工具提供定位；不使用一个总分掩盖缺失步骤。
- **错误决定修复位置。** 锚点角色错先修图；目标/方向错修条件；首尾正确但中间乱跳考虑事件锚点或受控视频编辑；长程失败修事件边界；接口失败只修协议。每次修复仍核验全片，防止局部修好后其他部分变坏。

这些是待验证主张。符号约束、关键帧条件和局部修复各自已有工作，不能单靠模块命名宣称首创。应展示它们在跨本体配对中具体解决了哪类错误，以及能否提高相同预算下的合格产率；文献与更完整设计见 [方法审查](PIPELINE_FAILURE_METHOD_REVIEW_20261020.md)。

## 6. 接下来如何形成论文证据

先固定一小批覆盖不同机制的真实来源任务和仿真布局：取放/容器关系、开合/关节对象、带前置步骤的长程操作。每个任务必须先有真实窗口与来源，不能为了方便生成而临时改任务。后续新增目标若来自组合推导，要另标“派生目标”，不能冒充已有真人演示。

分别做三类对照，避免一次换所有部件：

1. **审查：** 同候选视频、同图像/调用预算，均匀帧对比自动异常窗；另报告整视频VLM。使用独立逐帧人工核验集评估错收、错拒、时间定位和unknown覆盖。
2. **生成：** 同来源、布局、模型、预算，普通首帧prompt对比固定角色/事件条件；事件锚点作为单独一组，不混入prompt单因素组。
3. **修复：** 同失败集合、同追加预算，随机重抽对比错误定位后修复。计算独立合格配对数/全部尝试数、实际费用/合格配对、人工分钟/合格配对，并统计是否只会修简单取放。

还要检查：同一初态下不同目标是否仍可区分；新的外观/布局是否带来真正覆盖，还是只重复同一种动作。不能用“通过率更高但只留容易样本”来代替高质量泛化数据。

真实人类视频的状态和事件需要独立人工核验；仿真状态来自引擎；生成像素必须单独检查。仿真接触是真值，只对仿真本身成立，不能直接给生成的人手视频贴上接触真值。

当前不启动训练。数据侧方法稳定之后，再用固定模型做收益验证；真实机器人迁移需要另行实测。
