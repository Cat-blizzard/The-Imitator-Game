### 视频对照：首尾条件不是必然更好

首轮3个任务×2组，6条视频全部生成。下表是来源对照与可见证据检查，不是机器人任务成功率：

| 任务 | A：首图＋完整任务提示 | B：相同首图提示＋终态图 |
|---|---|---|
| 苹果搬运 | 搬运、释放和终态有可见支持 | 搬运已完成，但191→192帧从右碗跳回左碗，与错误终图一致 |
| 合书入箱 | 放入箱内并撤手有可见支持 | 放入箱内并撤手有可见支持 |
| 开右柜门 | 开门完成，但隐藏的小立方体被改成大彩色格板 | 开门、撤手和小立方体保留有可见支持 |

按这份小样可见证据，初轮两组均为2/3，**没有得到“加终图总体更好”的证据**。本轮观察到两种失败模式：无终态图的柜门样例改变了隐藏物体；苹果样例的错误终图与末帧目标回退一致。这支持“补足隐藏状态条件、先核验条件图”的后续假设，尚未隔离单模块因果贡献。

首轮共15次已开始的API调用：图像3、视频6、审核6。4份结构化审核有效；苹果B审核返回状态不明，没有重发；柜门A原审核返回了内容，但`limitations=[]`未通过预定格式校验。两次均保守占用调用预算，收费情况未核实。柜门A原始审核的七项全为yes，仍漏看小立方体变大格板，说明**模型回答“对象存在”不等于保持身份、比例和空间关系**。

原始协议、逐项审计及API真实输出信息见 [首轮对照报告](CONTROLLED_INITIAL_RESULTS_20261020E.md)。本轮审核与生成使用固定模型别名；中转返回格式有所不同，不能独立证明每次底层权重完全相同。

### 新的故障定位与纠错

加入了纯CPU的局部首尾突变诊断，不写苹果、颜色、碗或帧号规则。它先补偿估计的相机运动，再寻找局部区域相对于邻近时间的异常变化。六条视频使用同一组参数，只有苹果B的191→192帧触发，两个ROI分别落在物体消失和出现的位置；全局平均变化仅1.086/255，说明只看全帧平均容易漏掉任务关键小物体。

这套参数是在知道该缺陷后开发的，不是独立测试集上的检出率。已保存低对比漏检压力测试；它不会检测持续存在的错误对象，也不自动判任务成功。代码已接入 `automated_review.py`，有候选则输出连续帧复查请求，没有候选仍不能授予质量通过。[模块和限制](BOUNDARY_DISCONTINUITY_20261020E.md)

针对性修复采用剩余预算：苹果B改为在共同人类初图上执行明确的状态差分编辑；柜门A则保持原请求完全一致，再抽一次。两者属于看到首轮问题后的探索性修复，不能混入首轮结果。苹果终图的新方法目前由已确认的可见状态编写编辑指令，尚不是通用自动任务编译器。

两条修复均已完成，最终结果如下：

| 修复 | 实际结果 | 解释 |
|---|---|---|
| 苹果B：先修终图，再生成 | 新视频可见左→右搬运、释放、撤手；第191和192帧都保持右碗终态。同源码同参数的跳变候选由`[192]`变为`[]` | 本例终态回跳消失；同时重抽了视频，单例不能隔离改图与随机抽样各自贡献 |
| 柜门A：原请求再次抽样 | 仍将小立方体变成较大的彩色格板；VLM再次七项全yes | 当前请求缺少有效的隐藏对象约束，重抽没有解决；审核器也未识别身份／比例错误 |

初轮仍为A 2/3、B 2/3；纳入后验修复后，本地可见标准下A为2/3、B为3/3。**这不是盲测的统计优势，也不是机器人成功率。** 最终共图像4、视频8、审核8次，含未知审核和格式失败，合计20次API调用。没有未知请求重发，也没有后台付费任务遗留；人民币账单未核对。

原始初轮审计未被覆盖。最终[后验总账](/mnt/sdg/datasets/real_sim_human_pipeline/controlled_20261020e/audit_posthoc/POSTHOC_AUDIT.json)保存父子请求、媒体和报告hash。苹果修复视频仍为`needs_review`，柜门重抽为`reject`，均未获得训练准入。

## 需要解决的实际问题

1. 规划器的 `Success` 不能替代对最终执行轨迹的验证。旧自定义 Screw 没有利用已计算的碰撞结果，也存在停滞误判；即使替换为已安装的官方 MPlib，实际回放仍出现报告成功而终点偏差数毫米的路径。
2. 原脚本把搬运高度固定为至少 0.31 米、把抓取朝向一直保持到放置；这会把本来可以完成的任务写成不可达的单一末端目标。修复应增加满足任务约束的合法解，而不是放宽成功误差或关闭碰撞。
3. 资产文件存在，不代表可用于仿真。视觉和碰撞必须共用坐标与尺度；“杯子”作为静态干扰物可使用保守凸包，但不能用填满杯口的碰撞体去生成“往杯里放物体”任务。
4. 首尾图正确不保证中间发生了正确接触。视频质量总分也不能判断是否偏离人物方案、物体是否曾跳变或关键动作是否缺失。

## 本轮实现的设计

### SceneForge：物理执行之前的独立校验

新入口位于 `human_to_robot_pipeline/strict_apple_adapter.py` 和 `strict_motion.py`。历史生产规划器和已归档轨迹保留。

- 每次规划保存方法、当前关节、世界坐标目标、规划原始返回路径、加密后的关节路径和末端 FK。
- 对实际输出控制点及其插值检查关节限位、起点连续性、单步幅度、工作区、局部下降区域和末端位姿误差；逐配置重算碰撞。
- 对搬运阶段，使用实际抓住后的物体与 TCP 相对位姿，将携带物体加入碰撞检查。抓取、离开源支撑、释放接触各有明确适用范围。
- 目标从当前容器和物体几何得到；候选目标仍需通过相同验收。
- 独立原生验收读取实际抓取、接触、释放、稳定支撑和非目标物变化，不能由规划器自己宣布任务成功。

这里的“整条路径检查”是按明确关节步长对所有输出路径加密检查；不声称数学上的连续扫掠无遗漏。物理执行后的接触和结果检查仍不可省略。

官方 MPlib 也明确区分机器人避障点云与携带物体碰撞，并要求附着物的位姿相对于机器人链接表示。[官方碰撞教程](https://motion-planning-lib.readthedocs.io/latest/tutorials/collision_avoidance.html)

### 资产和布局的扩增

先从已经下载到 SDG 的资产筛选，不重复大批下载。每个候选记录来源、许可、文件 hash、几何检查、显式工程尺寸和统一变换，输出视觉模型、保守碰撞模型和预览。

布局按位置、干扰数量、干扰类别、相机分别记录实际覆盖。声明的采样范围、通过粗筛的配置数、实际运行数、通过物理验收数和通过语义审核数分开统计。旧四个布局用于回归；新布局不能取代失败回归样本。

### EventGuard：条件构造的受限预算比较

初轮选择苹果搬运、合书入箱、打开右柜门三个已有来源，每个来源比较：

| 组别 | 初轮条件 | 若首轮出现失败或未知 |
|---|---|---|
| A | 共用人类首图＋完整任务、步骤、人物和不变量提示 | 保持任务条件的再次抽样 |
| B | 相同首图和提示＋来自仿真终态的人类终图 | 根据失败证据修正条件，再生成 |

同视频模型别名请求、8 秒、720p 请求参数；首轮同审核模型别名和24张采样帧，并提供同样来源证据。真实输出尺寸、时长与帧数另行核对；中转底层权重无法由别名独立确认。

每个来源每组的上限均为图像2次、视频2次、审核2次。首轮与修复轮分开统计；记录实际调用与返回用量。**这是相同调用预算上限，不是已经核对账单的等人民币消耗实验。** B 的终图成本必须计入，历史共用首图成本单列；不以多花钱但不报成本的方式宣布胜出。

该初轮仅6个视频，属于故障定位小样，不能估计可靠的统计优势。它使用历史三个已绑定来源，只比较条件构造管线，不能归因于本轮严格规划或新增家居资产，也不是整条Real→Sim→合成人类链路的因果消融。下一步需要固定更多来源、每源独立重复和独立盲评；仅在后端明确支持时才讨论控制随机种子。

## 比继续加提示词更值得做的改进

1. **按接触阶段规划。** 自由移动负责可达和避障；接触阶段负责相对几何、夹持、支撑和短程轨迹。对不同布局重求自由段，保留接触结构，避免同一条世界坐标轨迹机械平移。DemoGen 也将自由运动与物体接触技能分段处理，这是一条已有依据的工程路线。[DemoGen 论文](https://www.roboticsproceedings.org/rss21/p157.pdf)
2. **从仿真导出交互约束。** 不只导出首尾 RGB，还导出对象身份、显露窗口、手/物体相对运动、可见区域。使用它们定位视频的问题，而不是假设生成视频与仿真逐帧同步。
3. **生成器只修真正有问题的部分。** 人物数量错时修人物锚图；隐藏内容错时增加揭示状态条件；接触缺失时增加接触邻域条件或生成较短动作段。每次改动保留先前结果和来源，控制修复预算。
4. **把可见性作为场景设计目标。** 物理成功而抓取过程被遮挡时，优先在同一物理轨迹上选择合适相机或补视角；不要简单删除这类难布局，造成数据只剩下容易场景。
5. **注意生成接口能力的边界。** 只有首尾图控制时，不能声称已强约束整个接触过程。RoboMaster 的公开实现使用对象遮罩及分阶段机器人／对象协同轨迹控制，说明中间交互条件是可实现的方向；并不代表当前 Seedance API 已接受同等控制。[官方实现](https://github.com/KlingAIResearch/RoboMaster)

### 下一步的具体工程方案与验收方式

以下为基于本轮失败提出的实施方案，尚未当作已经跑通的通用模块：

| 优先级 | 怎么做 | 用什么证据判定有效 |
|---|---|---|
| 1：锚图状态编译 | 从已验收仿真的对象关系差分产生结构化编辑要求，如`in(apple,left)→in(apple,right)`及必须保持的对象；VLM只修正角色映射和歧义。先检查新锚图满足关系，再花视频预算 | 将错误锚图送入视频生成的比例下降；报告自动通过、人工修改、未知三种数量。苹果本例目前只有人工确认版 |
| 2：隐藏对象身份检查 | 从仿真首次显露和稳定终态导出对象及容器ROI；在合成人类锚图/显露帧中建立对应，再比较物体／柜格面积比、形状、相对位置和外观。对遮挡不足的帧输出未知，不把同色当同物 | 在固定的“小方块变大面板”等反例集及独立正常集上测误报/漏报；不同相机先做视角匹配，不机械比较像素面积 |
| 3：事件视角选择 | 在同一物理执行上试少量合法视角，用实际分割统计抓取、提升、释放的连续可见时长，同时约束目标像素面积、遮挡和镜头范围 | 保持命令与状态完全相同，比较关键事件可见性；本轮0/16→16/16提供小样依据。保留困难视角作增广，另选清楚视角作参考 |
| 4：保留关键区域的局部编辑 | 如果全图编辑反复改变隐藏物体，先在规范视角把对象和柜格几何渲染正确，编辑人物及背景区域；按mask合成后检查接缝、遮挡次序。只有接口实际支持时才调用局部编辑，否则另列离线合成实验 | 比较对象身份保持率与整体自然度，公开蒙版和接缝失败；不把静态贴图正确等同于动态接触正确 |
| 5：接触事件短段生成 | 在接近、接触、释放的合法边界分段，逐段用前段实际终帧承接；验证共享状态再接下一段。额外视频调用必须计入相同总预算 | 检查无接触位移、对象跳变和边界速度异常；同预算比较完整合格片段/完整任务产率，不能只汇报最佳短段 |

规模实验应先冻结来源、评判规则和修复策略，再使用未参与本轮调试的人类来源及仿真布局。按每源实际生成/图像/审核用量分层报告有效候选产率；审查员不知道A/B，保留失败、不确定和所有修复轮次。至少同时报告任务保真、关键事件证据、对象身份和连续性，不能只报一个VLM平均分。当前没有已验证的货币单价，不能预先宣称等费用比较已经完成。

这些改进是否构成论文贡献，取决于固定预算下的有效配对产出、困难机制覆盖、失败纠正率及后续训练收益。模块命名和工具数量本身不证明创新。
