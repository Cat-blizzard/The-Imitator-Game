# 首尾局部突变诊断：CPU 模块与 6 段固定参数验证

本模块在不使用任务名称、颜色条件、人工 ROI 或特定帧号的情况下，定位到 apple/B 的 **191→192 帧**两处局部变化。apple/A 正常对照没有首尾告警；其余四段也未产生首尾候选。这里的结果是“应查看的帧和区域”，不是任务成功/失败或物理合理性的自动判定。

代码：`r2h_pipeline/boundary_discontinuity.py`。批处理入口：`run_boundary_discontinuity_20261020e.py`。

全部证据：

```text
/mnt/sdg/datasets/real_sim_human_pipeline/controlled_20261020e/boundary_diagnostics/
```

其中 `apple_B/candidate_sheet.jpg` 可以直接查看 191→192 帧与两个黄色候选 ROI；原始解码 PNG、视频/帧 hash、实际 PTS、处理分辨率、全部相邻帧分数都在对应目录内。没有运行 GPU、API 或训练。

## 怎么发现全局统计不明显的小变化

1. **连续读取每一帧**，用 ffprobe 的真实 PTS 与解码数量核对。计算最多 512 像素长边的 RGB 差异，没有均匀抽几帧替代连续检查。
2. 对相邻帧做 KLT 跟踪与 RANSAC partial-affine 拟合，抵消主要相机变化；拟合不可靠时明确记录 identity fallback。它只是背景运动代理，没有语义背景分割。
3. 去掉全图每通道的中位亮度偏移后，计算每个像素最大通道残差。这样全局曝光变化不会轻易冒充局部物体变化。
4. 用 **32×32、步长 16** 的重叠 tile 统计最强 **12.5%** 像素残差，避免小物体变化被整幅图平均掉。
5. 用相邻 ±12 个 transition、排除自身与直接相邻 transition 的活动，估计局部正常残差。额外参考周围 2 格 tile，减少平滑运动进入新 tile 的误报。采用中位数和 MAD，得到启发式 robust z；它不是高斯概率或“六西格玛置信度”。
6. 同时要求 tile 能量≥12、相对正常活动的超额≥10、能量比≥3、robust z≥6。候选 tile 内取像素残差≥12、形态学闭运算后至少 8 像素的连通区域，输出 ROI。
7. **只有首尾 0.5 秒的候选进入复核包**；全片相邻帧的分数仍保留。可以将其送给人工或已有 VLM 做针对性复核，但本模块不自动接受/拒绝训练样本。

这是离线质量诊断，会使用邻近未来帧建立统计背景；不是因果预测模型，也不是动作或接触监督。

## 这次结果

全部使用同一份冻结配置，每段 193 帧、192 个相邻 transition 都参与计算。每段 CPU-only 运行约 9–10 秒，批处理并行度为 2，每个进程 OpenCV 线程数为 2。计时是 CPU-only 作业的墙钟时间，不是 CPU 核时。

| 视频 | 首尾候选帧 | 首尾最高 robust z | 能说明什么 |
|---|---|---:|---|
| apple/A | 无 | 4.88 | 已知正常对照未告警 |
| apple/B | **192** | **36.83** | 命中已报告的末帧局部跳变 |
| book/A | 无 | 5.58 | 未检出；不是质量通过 |
| book/B | 无 | 1.29 | 未检出；不是质量通过 |
| cabinet/A | 无 | 1.82 | 未检出；不是质量通过 |
| cabinet/B | 无 | 2.31 | 未检出；不是质量通过 |

apple/B 最后一个 transition 的全局平均残差仅 **1.086 / 255**，但最强 tile 达到 **96.25**。之前 4 个 transition 的最高 robust z 都低于 0.43，而末帧达到 36.83。两个 ROI 分别位于原目标位置的消失区域和另一位置的出现区域，原图像素坐标为：

- `[555, 498, 623, 559]`
- `[320, 508, 390, 569]`

算法没有将它们识别为苹果或碗，也没有推断物体身份。上述语义解释来自对复核图和已报告问题的人工阅读，不能倒写为算法 ground truth。

## 误报、漏报与验证边界

**这不是盲测。** 开发前已经知道 apple/B 的末帧问题与 apple/A 对照。`development_protocol.json` 在真实视频得分产生前固定了参数、输入列表和 detector source SHA；六段使用相同参数，没有看到结果后调阈值。冻结源码保存在 `detector_source.py`。

- 对已有标签的单个正例：报告的问题被命中，未观察到该问题的漏报。
- 对已有标签的单个正常对照：没有观察到首尾误报。
- 其余 4 段没有完整逐帧突变标注，**不能计算总体 precision/recall，也不能称作 6/6 正确**。
- 7 项合成测试通过：静止/全局亮度变化、平滑局部运动、整体相机平移不触发；三种不同颜色的小区域末帧跳变能够定位消失与出现两处；时序上下文不足保持 unknown。
- 另做了固定参数的低对比压力测试，明确看到了漏检，没有据此降低阈值：

| 10×10 像素区域的附加对比度 | 已知末帧发生跳变 | 是否检出 |
|---:|---|---|
| 5 / 255 | 是 | **漏检** |
| 10 / 255 | 是 | **漏检** |
| 20 / 255 | 是 | 检出 |
| 40 / 255 | 是 | 检出 |

压力测试使用随机种子 931、固定 160×192 灰度纹理背景、10×10 区域在最后一帧从 x=24 跳至 x=142，配置与真实六段相同。记录在 `synthetic_contrast_stress.json`。它只展示某种对比度/尺寸组合下的边界，不代表真实数据上的召回率。

正常的快速手部运动、遮挡边界、局部光照或相机拟合失败仍可能造成误报；很小、低对比的变化，以及连续但错误的任务状态可能漏检。一个错误状态如果一直稳定存在，也不会因为“没有时序突变”而被发现。模块不得代替实体身份、任务顺序、接触和结果检查。

## 接入现有 pipeline 的方式

在生成的视频落盘、SHA 与时间轴验证完成后运行此诊断。若输出候选，将候选 transition 前后连续帧与局部 ROI 加入已有复核请求，询问“是否发生突变、是否只是正常运动/遮挡、哪些证据仍 unknown”。无候选时继续原有质量流程，不能自动通过。

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 PolicyGen/.venv/bin/python \
  -m data_generation_methods.r2h_pipeline.boundary_discontinuity \
  --video /absolute/path/candidate.mp4 \
  --output /absolute/path/new_immutable_diagnostic

OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 PolicyGen/.venv/bin/python \
  -m pytest data_generation_methods/tests/test_boundary_discontinuity.py -q
```

没有修改 dispatcher、核心仿真或收费 API 路径。批处理首次汇总时曾因通用写入函数拒绝覆盖 progress JSON 而报错，六个 worker 已完成的报告全部保留；随后只从这些报告恢复了总表，并将未来 progress 改成编号文件。检测器和阈值未变，也没有重跑或删除不利结果。
