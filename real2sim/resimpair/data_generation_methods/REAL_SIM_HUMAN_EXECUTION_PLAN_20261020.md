### 首个生成失败揭示的真实缺口

首帧红苹果在右碗，0.125秒时在手还没抓取前跳到左碗，最后人手把它搬回右碗。整段画面看起来像一次自然搬运，但没有完成相对于原初态的目标。逐帧证据和颜色诊断在 `seedance_recovery/first_second_contact_sheet.jpg`、`red_object_color_diagnostic.json`；拒收记录为 `quality_rejection.json`。

独立VLM文字描述把初态当成左碗有苹果，未发现前0.125秒跳变。原因尚不能归结为模型推理能力，可能与视频采样或时序摘要有关；不能用这个单样例统计误检率。这直接支持补充：强制首尾帧、短时连续跟踪、异常时间窗口密集采样，再让VLM解释疑点。

不能静默剪掉开头再当作保持原初态的生成结果。若重定义为一个新的完整子窗口，必须重新核验初态、角色、目标、时钟与配对用途，并放弃“同原始锚点分支”资格。

## 先澄清两种不同的迁移

AI生成的人类视频是synthetic human，不是重新采集的real。它解决的是参考来源不足，不能自动解决PolicyNet面对真实机器人图像、传感器和控制器的域差距。

```text
真实人类视频/真实任务需求
    → 带证据的任务定义
    → 可执行的机器人任务 + 布局/几何/目标扩充
    → 原生机器人执行及状态、动作、接触记录
    → 任务受约束的人类视频候选
    → 独立检查和局部纠错
    → 同目标、跨布局的参考—机器人配对
    → 固定训练协议的策略学习
    → 真人参考测试 + 真实机器人观察/控制适配与测试
```

**特别重要：任务一致不等于物性一致。** 人在塑料杯中拿苹果，机器人在陶瓷碗中拿苹果，目标可以等价，但容器摩擦、物体质量、顺应性和接触几何未必相同。不能用“同一个任务”配对，就把人类参考解释成目标机器人环境的动力学标签。

建议配对记录明确声明用途：

- `task_only`：可监督目标、对象角色和必要顺序；跨场景、跨本体允许。机器人action仍来自机器人自己的观察/执行。
- `motion_correspondence`：额外有可核验的相机/时间/对象轨迹对应，才使用对应范围的运动监督。
- `dynamics_matched`：参考与执行的机制/物理参数有明确匹配证据，且视频中的响应确实可观察，才研究物性相关迁移。当前普通语义配对不自动具有这个资格。

这些是推荐的数据用途标签，不意味着当前reader已支持全部路由。

## 论文应押注的主张

Zero-WAM已经做机器人轨迹→人类参考视频及VLM筛选；SimFoundry已经做视频→仿真场景与对象/布局/任务变体；NeSyCR已经做视频程序抽象、跨域检查与修复。因此串联这些能力、再包装一个agent，创新证据不足。

建议当前中心假设：**将真实视频中的对象角色、初终态和必要事件作为贯穿生成过程的不变量，用证据驱动的审查定位失真，并据此选择修复位置，可以在相同调用预算下提高任务等价配对的有效产率。**

这不是已被证明的新颖性声明。它要求三个环节一起成立：

1. **任务身份有来源。** 人类原窗口定义的角色、初态、必要动作和结果能映射到仿真；允许换布局和外观，但不得在生成失败后修改原目标来迁就结果。
2. **错误有独立证据。** 仿真记录检验机器人执行；生成视频自己的像素证据检验人类侧。强制首尾帧、对象连续性与异常窗口复核补足全视频概括的盲点。不能用仿真真值替生成像素背书。
3. **修复比盲目重抽有效。** 角色/目标错、静态锚点错、短时跳变、长程漏事件、纯接口失败分别路由，冻结验收要求，记录每次调用和失败；比较等预算下的独立合格产率、错收率与人工时间。

同初态多目标仍是重要的数据侧压力测试：一组视频不能只是各自看起来合理，还应让独立盲读恢复不同目标。两个目标都被生成成同一种常见动作时，整组信息保持失败。每组共用目标无关的人类初始图，人物/背景/生成模型跨目标交叉分配。它目前不需要启动策略训练。

未来需要验证数据对模型的收益时，再用固定训练协议和真实人类参考做下游实验；不把当前工作重新转成HyperNet架构搜索。关键帧条件、符号检查与局部修复已有相关工作，必须由具体对照证明组合中的实质方法改进，而非声称每个组件都是首创。

新增目标如果没有原始真人片段，就明确标为“从原任务派生的新目标＋合成参考”，不能谎称原人类视频已经演示它。严格真人对应的数据层继续保留。

## 流水线如何落地

| 环节 | 输入与真实产物 | 应做的校验/纠错 |
|---|---|---|
| 真实视频理解 | 完整任务窗口；对象角色、初态、结果、必要顺序及未知项 | Gemini先盲读可见事实，再对关键时刻复核。不能只用一句caption，也不能把遮挡中的力或状态猜成GT |
| 仿真任务编译 | 有尺度/碰撞资格的资产；对象相对技能；机器人可达目标 | 复用现有SAPIEN/ManiSkill/MPlib路径，重新规划后真实执行。失败改规划、资产或控制，不改验收标准 |
| 扩充场景和机制 | 合法布局、真实几何、关节/容器可供性、多目标组 | 数量按机制和目标分支覆盖统计；新纹理不算新机制。新源会话/资产家族提前划split |
| 原生证据导出 | RGB/PTS、K/外参、depth、对象/机器人mask、状态、接触、action | 仿真已知的量直接导出；不让VLM重新估计。当前depth/dense-mask尚需补接 |
| 合成人类参考 | Nano图像锚点；Seedance语义生成或视频编辑；必要时VACE受控编辑 | 区分任务等价与运动保持。闭源API不一定支持mask/depth，不能假装prompt能硬性约束几何 |
| 生成后检查 | 对象身份、关系、事件、跟踪、遮挡与边界证据 | 媒体完整性→独立视觉工具→VLM语义解释；unknown拒绝升级为高精度监督 |
| 定位后修复 | 具体失败时间段和原因 | 目标错改任务条件；身份漂移改角色锚点；接触/遮挡错误换受控路线；长段断裂修边界。修复后整段重新验收 |
| 配对与训练 | 执行A生成参考H_A，配同目标独立布局B的观察/action_B | 不拿A的action配B的观察。冻结原模型/动作空间/训练预算，先只比较数据方法 |
| 真实部署 | 真人参考＋真实机器人RGB/proprio/反馈 | 实测相机、控制频率、EEF坐标/旋转约定、执行延迟/限幅；真实机器人图像和控制差距另做实验 |

**任务要求不是机器人脚本全序。** 用户只要求把苹果换到空碗时，不应强制人手复现机器人每次停顿或同一抓法。真正必须的顺序是抓取/移出/释放等语义约束；不同任务的事件可有重叠，需要显式约定比较的边界。

## 工具选择与能力边界

- **Gemini**：任务窗口、对象角色/事件提取、匿名辨别与错误定位。不能取代物理测量，也不能用自报0.9当90%正确率。
- **Nano Banana**：人类初始锚点、外观参考和必要局部图像修复。不是视频模型，图像好看不能证明动作正确。
- **Seedance**：连续人类视频候选。本轮已测试的请求是first-frame语义生成；严格视频编辑仍需可访问源视频URL/asset以及独立校验。
- **SAM 3/分割 + CoTracker**：估计对象身份、可见轨迹和消失/复制/跳变。跟踪也会错，遮挡应保留未知；近接不等于接触。
- **仿真mask/depth/camera + VACE**：闭源编辑无法保持关键运动时的可控对照，不承诺装上就能保证接触。
- **trimesh/碰撞处理/原生物理执行**：资产尺度、内腔、轴、碰撞几何和稳定性。不可把碗整体变凸包堵住内腔。
- **SQLite/JSONL/FFmpeg**：请求账本、完整媒体与时钟、来源hash、重复提交防护。当前规模不需要先搭复杂分布式平台。
- **SimFoundry**：作为重建/资产/场景构建组件和强基线来评估；它的开源README仍区分已放出的场景生成与后续数据生成/训练组件，不能假定整篇方法已可一键复现。

## 后续模型研究备忘：不属于当前执行阶段

对闭源图像/视频API，只能进行条件生成、结果评分、筛选和修复；不能把我们的轨迹误差说成已经反传给Seedance。

策略训练优先保留当前稳定的action/flow-matching loss。通过同初态多目标样本，使机器人观察自身无法唯一确定正确action，再检验HyperNet参考是否被使用。不要先增加W范数分离loss：参数差异不等于行为差异。

如果确实研究动力学，需独立构造**同目标、不同可观察物理响应**的试验，并确保参考与目标场景机制匹配。例如对象释放后的可见滑动衰减可约束某些有效动力学；普通RGB没有已知输入力时，不能直接识别绝对质量。真实目标环境的未知摩擦/负载，最终往往需要机器人自身观察—动作—反馈来估计。

一个值得后续单独消融的架构分工是：人类参考生成稳定任务参数；机器人近期反馈估计当前环境动力学状态。它尊重“参考跨场景”这个条件，也避免让HyperNet每步改参数造成抖动。本轮没有修改或训练该架构。

## 第一批研究试验，先做小闭环

建议先两到三种机制：取放选择、开合/访问、带必要前置步骤的取物。每类先4–6个布局、2个目标，目标互斥且都可执行；这只是建议，尚未启动收费批量。

固定同一批机器人轨迹、同生成后端、同调用预算，比较：

| 组 | 生成/验收方式 | 能回答什么 |
|---|---|---|
| A | 普通任务文字＋首帧，单条VLM检查 | 强API的朴素基线 |
| B | 显式角色/初终态/必要事件约束，独立视觉检查 | 减少语义和交互误配是否有效 |
| C | B＋同初态多目标整组辨别＋定位修复 | 任务差异是否真正保留，而非都生成常见动作 |

数据侧报告完整事件率、错误接收率、目标混淆、每条独立合格参考的实际成本、重试和失败分母。
人工核验开发样本用于阈值校准；伪造/缺事件/调序/对象消失等负例必须与最终测试分开。

模型侧固定CNN/EEF基线、初始ckpt、原数据比例、总更新预算。比较普通扩量和分支组扩量，测未见布局/资产/组合、真实人类参考，以及参数合法互换后的目标成功矩阵。为证明HyperNet自身价值，需要同编码器、接近参数/算力预算的向量条件/FiLM/cross-attention对照。

真机侧必须同时测原真人参考和合成参考，独立报告仿真→真实差距。没有设备测试之前，只能声称完成配对生成或仿真泛化，不能写“实现真实部署”。

## 下一步优先级

1. 本次Seedance只读恢复已取回并拒收视频；下一轮先处理初始连续性及结构化输出协议问题，不直接重复同prompt扩量。
2. 将新通用契约接到真实苹果任务的生成、审核和训练候选导出；现有积木CLI不强行套用。
3. 补原生mask/depth/camera；实现一种可靠对象跟踪接口，再用明确错误样本校准门控。
4. 从一组同初态两目标开始验证“生成后仍可辨别”；不立即花钱生成上千条。
5. 先完成数据侧等预算对照和独立人工核验，再考虑下游收益实验；当前不启动模型训练。
