# 机器人视频转人类参考：方法研究与判断

核查日期：2026-10-19。依据一手论文、官方项目、代码和公开配对清单；未运行生成模型，未验证其在我们数据上的效果。以下“建议”是我们的设计判断。

## 结论

值得尝试，但首先应明确产物是**合成的任务参考**还是**保持原运动的本体替换视频**。Zero-WAM属于前者；许多被一起讨论的工作实际是人类转机器人，或生成未来计划，不能直接反向调用来完成人类化。

对我们最快可验证的路线是：从已有合格机器人轨迹得到可核验的任务说明，制作合成人类参考，保持机器人端真实RGB和原生动作不变；再用同任务、不同布局的机器人执行配对训练。它能降低配对成本，但不会自动增加新的任务或真实人类经验。

若目的是让W预测可靠的3D运动或接触响应，纯RGB生成不提供这种真值。应另用已知仿真状态、明确的人手模型轨迹，或原有真实腕部标注。

## 主要方法及方向

| 工作 | 实际处理 | 对我们可借鉴之处 | 不能据此推断 |
|---|---|---|---|
| [Zero-WAM / HumanGen](https://arxiv.org/html/2608.26103v1#S2.SS2) | 机器人任务分析→编辑首帧→生成人类操作视频→VLM筛选；允许改变场景、物体与视角 | 从有动作的机器人数据反向补任务参考，按任务覆盖采样 | 人类视频与机器人逐帧对齐、动作和接触保真 |
| [Gen2Act](https://homangab.github.io/gen2act/) | 当前场景和语言→生成人类未来示范→视频条件机器人策略执行，配点轨迹辅助 | 生成视频可以充当可视化任务计划；无需把人类像素当机器人动作 | 它是已有机器人完整轨迹的精确转写器 |
| [Phantom / Masquerade](https://github.com/MarionLepert/phantom) | 人类视频估手姿、移除手臂，再覆盖渲染机器人 | 分离本体与原物体画面，复用pose/mask/inpaint/render工程 | RGB估计深度能自动成为可靠3D action；Masquerade使用二维未来点辅助 |
| [H2R-Grounder](https://showlab.github.io/H2R-Grounder/) | 人类→机器人；背景视频与位置/朝向提示共同条件化Wan视频生成 | 保留动态场景条件，显式控制运动而非只写文字 | 生成器严格不改物体，或输出已执行验证的机器人动作 |
| [MimicDreamer](https://arxiv.org/abs/2509.22199) | 人类ego→视角稳定、IK运动与渲染先验→机器人视频 | 同时考虑相机、运动可达性与视觉本体差异 | IK可达等于抓取和动力学成功；单应变换能处理任意3D视差 |
| [Robotizing Human Videos with Physically Consistent Interactions](https://arxiv.org/abs/2610.06137) | 人类→机器人；加入接触对重建与深度遮挡处理 | 接触位置与前后遮挡比单纯复制腕部中心更关键 | 估计接触或深度就是测量到的力学真值 |
| [Mirage](https://robot-mirage.github.io/) | 机器人→另一机器人；执行时按EEF渲染已知本体，并转换控制 | 可确定地替换本体、保留真实环境反馈 | 已有可直接运行的人手生成器 |
| [DreamGen](https://research.nvidia.com/labs/gear/dreamgen/) | 生成机器人视频，再由逆动力学/潜动作模型提供伪动作 | 可借鉴生成质量与下游策略收益分开评估 | 伪动作与我们仿真原生命令等价 |

开放实现核查：Phantom/Masquerade和Mirage有处理代码；[H2R-Grounder仓库](https://github.com/showlab/H2R-Grounder)目前仍称代码与模型待发布；[MimicDreamer仓库](https://github.com/GigaAI-research/MimicDreamer)本次仅见README与LICENSE。2026年10月的接触/遮挡改进论文未确认公开实现。因此不能把全部论文作为现成组件排期。

## Zero-WAM具体提供了什么

论文的生成流程使用Gemini 3.1 Pro或Qwen3.6-Plus分析任务；Nano Banana 2或Qwen-Image-2.0编辑首帧；再编写操作描述，使用Wan 2.7或Kling 3.0生成视频，最后VLM审核。策略本体的Wan-2.2-5B与这些数据生成模型不同。首帧如何作为实际API条件、时序参数、完整prompt和失败重试规则未公开，不能用常见I2V接口补写成源码事实。[论文§2.2](https://arxiv.org/html/2608.26103v1#S2.SS2)

我们独立重算了官方RoboTwin配对manifest：

| 指标 | 公开文件实测 |
|---|---:|
| 配对行与不同机器人路径 | 2,499 |
| 不同人类视频路径 | 994 |
| 任务根目录 | 50 |
| 被多个机器人使用的人类路径 | 800 |
| 人类路径跨任务根复用 | 0 |

头部计划为2,500，最终合格行2,499。文件明确包含同任务参考复用，因此不能把pair数当独立人类视频数。路径去重不是视频内容去重；同任务根也不自动证明每个细粒度对象选择相同。全部保留行的两个评分均为5，无法据此恢复筛除率或校准评分器。

小型原始证据、来源和可复算脚本：[sources/zero_wam_20261019](sources/zero_wam_20261019/SOURCE_INDEX.json)、[统计](sources/zero_wam_20261019/manifest_statistics.json)。源文件为[官方配对清单](https://huggingface.co/datasets/Robbyant-Research/HumanGen/resolve/main/icl_configs/ICL_config_robotwin.json)。

截至核查日，[官方仓库](https://github.com/robbyant-research/Zero-WAM#humangen-data)已提供外部数据和RoboTwin的机器人数据、双方latent、配对表，以及生成的人类MP4压缩分片。此次HF目录核查为7个human分片，约69.24GB，未下载或解码；不能再沿用“只公开latent”的旧说法。官方代码commit为`08e2c4ae41e2b63573a299825cebe6753481407c`；本次未找到完整R2H生成及VLM质检脚本。内部与自采实机子集不在README声明的两个公开子集中。

## 三种可实施路线

### 路线一：任务语义重生成，优先做可行性验证

从仿真成功日志提取对象角色、初态、必要事件和终态，用视频复核；VLM负责把这些事实写成自然人类操作说明。图像模型制作初始人类场景，视频模型生成完整操作。允许速度、手姿、背景和布局变化。

优势：不需要逐帧重建人手，能直接补当前缺少参考的任务。局限：容易跳过必要步骤、选错物体、丢失方向、以不合理接触完成目标。最适合目标级参考学习，不适合继承原机器人时间对齐的腕部监督。

对当前模型：合成视频进入HyperNet参考编码；原机器人画面和真实动作仍进入PolicyNet及动作loss。全参考可用于任务理解；未来视觉辅助必须另用因果前缀。合成人类腕部loss默认关闭。

### 路线二：受控视频编辑，测试能否保持运动

输入原生视频、显式本体mask、参考人手外观及可用的深度/位置条件，用视频编辑模型替换机器人。先固定相机、对象和时间，再尝试外观变化。不采用独立逐帧图像编辑作为默认方案。

重要困难：机器人被移除后露出的背景此前不可见；人手形状改变也会改变遮挡和接触轮廓。简单把mask外原像素贴回并不能保证接触正确。视频生成器接受mask也不等于提供硬像素约束。

适用：参考域适配、运动与事件保持研究。原机器人action仍只监督原机器人流；只有独立核验过的对应量才能进入跨域运动loss。

### 路线三：几何与接触约束渲染，再作外观修饰

当源仿真记录有足够对象状态、相机、深度和接触时，固定对象运动，重定向到明确的人手/上肢模型。优化抓取接触区域、释放、可达性、连续性和穿透，再按深度合成。生成模型主要补外观及小区域缺失，不负责决定物体去哪儿。

这是更适合精确3D标签的长期路线，但不能把机器人TCP直接当人腕：腕部坐标与夹爪中心存在偏移，二指抓取与五指接触不同，上肢可达范围也不同。只有人手模型真实使用的轨迹才有可知的合成3D标签；它仍是合成标签，不是真人测量。

## 相比直接复刻HumanGen，我们应增加的设计

1. **用原生日志约束任务事实。** 初态/终态和已记录事件优先来自仿真，VLM核对可见性并表达，不凭语言补造力、摩擦、锁扣或顺序。真实机器人数据缺失的字段保持未知。
2. **区分动作选择与外观变化。** 同目标多外观是正例；同一机器人初态的不同合法目标用于检验参考控制行为。对新目标参考的成功应按新目标评分，不能只当原目标失败。
3. **跨执行配对。** 由rollout A生成的参考优先配同一精确目标、不同布局的rollout B；A、生成参考、B必须同split，A的所有生成后代沿用来源划分。PolicyNet的观察和动作均来自B；不能把A的动作贴给B。保留A→A作为诊断对照，避免只学同场景轨迹复制。
4. **用事件链检验生成质量。** 检查选择对象、抓取/接触、搬运、释放/支撑、结果和非目标保持。严格路线增加轨迹与事件时刻比较；语义路线不要求像素或时间一致。
5. **评分器不是物理裁判。** 加入独立视频跟踪、对象存在性和关系检查；VLM对具体事件给帧证据，使用抽查校准误判。未接触却移动、目标瞬移和步骤省略应单独统计。可借[H2R-Bench](https://arxiv.org/abs/2608.13049)对目标、事件、功能接触、本体、视觉质量分开评估的思路；我们使用的是反方向适配，不冒称复现其基准。
6. **生成成本按合格率算。** 记录所有请求、失败与重试；成本=全部费用/独立合格参考数。重复风格版本不能增加任务数；少量参考复用不能增加真实人类会话数。
7. **最终必须测真人参考迁移。** 只在同一生成器的人类视频上成功，可能只是学会生成器风格；要保留真实Ego/原基准人类参考，跨生成来源与真实录制会话评价。

## 图像/视频模型的选择

此表只确认官方接口能力，不宣称哪个模型在本任务上更先进。账户权限、地区、速率与实际费用需要真正运行时确认。

| 候选 | 可承担的工作 | 当前边界与来源 |
|---|---|---|
| 本会话image_gen | 制作和编辑锚帧 | 工具未暴露具体模型ID，不能保证就是GPT Image2；没有视频生成接口 |
| GPT Image2 | 人类初始场景、参考外观、关键帧编辑 | 官方模态为图像输入输出，视频不支持；最多16图的编辑接口不等于时序编辑。[模型](https://developers.openai.com/api/docs/models/gpt-image-2)、[编辑接口](https://developers.openai.com/api/reference/resources/images/methods/edit) |
| Gemini Nano Banana 2.1 | 图像编辑、多图上下文 | 可接受视频上下文，但输出为图文，不输出编辑后的视频；需固定具体版本。[官方模型](https://ai.google.dev/gemini-api/docs/models/gemini-nano-banana-2.1) |
| Gemini Omni 1.1 Flash | 上传视频编辑，或视频生成 | 当前上传编辑输入不超过10秒，地区有限制；是否保住接触需实验。[官方文档](https://ai.google.dev/gemini-api/docs/omni) |
| Veo 3.1 | 参考图/首尾帧视频生成 | 此类控制不能替代任意源视频的逐帧编辑。[官方文档](https://ai.google.dev/gemini-api/docs/veo) |
| Wan / VACE | 视频、mask、参考图及深度等条件的本地编辑 | 有官方代码；安装、显存与我们数据的质量尚未实测。[官方仓库](https://github.com/ali-vilab/VACE) |
| Wan 2.7 / Kling 3.0 | HumanGen论文所用视频生成后端 | 论文使用不等于本环境已有API权限；本轮没有接入或比较 |

图像模型只解决锚帧，连续视频模型和验收更可能决定最终可用率。当前没有证据支持“GPT Image2必然比Nano Banana更适合我们的接触任务”。最有价值的比较是相同输入、相同事实约束、相同预算下的合格率、事件完整性和成本。

## 范围与研究意义

从机器人生成的人类参考不会带来源机器人轨迹之外的真实任务经历；生成器的先验也不是物理事实。该方向的直接价值是降低跨本体参考构建成本、扩大外观与视角覆盖，并使已有机器人动作可以用于参考条件训练。

如果能进一步证明：跨布局合成参考改善了真实人类参考的执行，并且在同初态换目标参考时策略可靠地切换目标，才支持“学到参考中的行为信息”。若要提出物理规律的论文结论，还需真正可辨识的响应、接触或物性实验，不能由图像逼真度替代。
