# real → sim → synthetic-human：本轮小批量实测

日期：2026-10-20。按当前优先级完善造数管线，没有启动模型训练。本轮复用已有人类来源绑定的仿真执行，没有重新采集机器人轨迹。

## 产物与计数

| 项目 | 本轮实际数量 |
|---|---:|
| 独立真人任务窗口 | 3 |
| 任务类型 | 3：苹果换碗、闭合书入开盒、只开右柜门 |
| 人类参考候选视频 | 4：3条新生成，1条复用此前修复样例 |
| 新图像编辑／新视频生成请求 | 3／3 |
| 远端审查 | 10：3次初图对照、1次手数专项、6次视频审查 |
| 显式跨执行参考→机器人配对 | 4 |
| 实际CPU输入读取／拒绝 | 12／0 |
| 自动完整任务证据验收通过 | 0；4条均为`needs_review` |
| 物理／三维运动验证、正式训练准入 | 0／0 |

总计16个付费阶段请求，不等同于16个成功样本。原始格式失败、补审、额外检查均计入。轮询恢复没有重复提交视频。无法从这些请求记录推算账户实际收费金额。

最终软件检查为369项测试通过；它验证接口、解析、证据规则、配对与读取逻辑，不代表369次视频生成或任务成功。结构化汇总见[BATCH_REPORT.json](/mnt/sdg/datasets/real_sim_human_pipeline/batch_20261020b/BATCH_REPORT.json)。

4条参考均为实际24fps、193帧、960×960、约8.042秒；机器人仍使用原始20Hz时间轴。两个苹果布局来自同一个真人任务窗口，不能算两个独立真人来源。这是流程诊断小样本，不是模型生成成功率评测。

## 本轮发现并处理的问题

### 1. 接口与审查格式会阻断流程

中转返回`pending`，旧适配器只认`queued/running`，使已经在服务端运行的视频被误报为接口失败。现在将已观察到的`pending`明确映射为`queued`，保留原状态，只GET恢复原task ID。

审查模型有两类真实格式错误。第一类把查询定义当输出并漏字段，保留拒绝；提示词补入与本地校验相同的完整schema。第二类字段、值和证据均完整，但将事件数组输出为单对象。新增确定性兼容器只做`object → [object]`，逐项记录内容hash；本次白碗8处包装，0次额外API。它不补真值、时间或证据，不改原失败记录，也不将格式通过解释为任务通过。

### 2. “整体看起来对”会漏掉具体错误

柜门初图的综合审查给了通过，但独立复核看到左侧1手、右侧交叠2手。专项手数审查返回最小2只、精确数量不确定；新增门控将这种情况留为`needs_review`。不能说专项VLM已经准确数出3只，也不能把多个人的手误称为解剖学不可能。问题是编辑结果偏离原定两臂替换方案，且综合审查没有发现。

当前专项模块已实现并实测，但尚未默认插入所有批量任务的生成前置关卡。下一批应明确演员/手数量预算，并在初图合格后才付费生成视频。

### 3. 缺少关键时刻时，应补观测

书本首轮24帧审查对抓握标为未知。新的预算选择器读取实际`refinement_requests`，优先完整覆盖短区间：

- 定位原生帧68–79，共12帧；
- 原包已有两端点，补入69–78共10帧；
- 34帧重新审查后，在76帧、3.166667秒建立抓握里程碑；
- 全片193帧的禁止事件覆盖和另一46帧区间超预算，明确保留未解决。

这是一次有界的实际补帧→重审；不是无限自动重试，也不能据此估计补帧的总体因果收益。选中了连续帧不等于必然能看见遮挡中的接触。

### 4. 首帧条件缺少隐藏状态，这是主要生成瓶颈

柜门关闭时，看不到内部物体。当前Seedance只接收**编辑后的首图＋文字**，并没有接收机器人整段视频、开门后的图、mask/depth或运动轨迹。即使生成器正确开门，也没有足够条件可靠保持柜内对象身份。

本例不能断言彩色块消失：生成柜内较暗，可能不可见。但它已足以暴露条件不足，不能因为“开门动作对了”就接受所有隐藏状态。

后续需要从仿真导出任务关键状态，包括接触前、接触中、暴露隐藏物体、完成后，并在确实支持这些条件的生成路径中使用；生成后逐对象核对。只把所有要求继续堆进文字prompt，不会提供缺失的视觉信息。当前尚未实现通用多关键帧条件、视频局部重生或几何约束生成。

### 5. 训练读取器会改变原定数据语义

实际代码审计发现旧生产读取器按同goal建立参考池，不严格遵守指定的参考→query边；还存在`synthetic_human`来源枚举缺口、派生视频跨split来源追踪不足、缓存key不含实际参考内容、默认动作offset可能偏一帧等问题。

本轮新增隔离适配器，使用显式配对、内容hash、来源lineage、独立时间轴和原生`target_start_offset=0`。没有宣称这些改动已经接入旧生产loader。

实际4条配对、每条首/中/末3个query，共12次读取：RGB与原生产图像函数逐像素相同；归一化action最大差`1.14e-7`、state最大差`4.33e-7`，末尾mask正确。参考输入为`32×3×224×224`，动作窗口`16×20`其中14维有效，state20维其中18维有效。这是数据读取校验，不是启动优化器。

[不可变输入检查快照](/mnt/sdg/datasets/real_sim_human_pipeline/batch_20261020b/training_pair_inspection_snapshots/ac81e404ed146b5638ca/)保留明确配对、源代码、固定样本检查和原文件hash。

## 如果后续用于训练，使用边界是什么

- **任务参考条件**：可以继续审核前三个可读候选，但需要单独的任务参考准入与正式loader接线。
- **机器人action监督**：只来自query B自身原生轨迹；不能拿生成参考所对应执行A的动作监督B图像。
- **未来视觉辅助**：可以从生成视频构造前缀→未来视觉特征，但生成伪影也会被学到；必须先检查事件、对象连续性。
- **人类腕部3D／动力学监督**：当前生成视频没有这些GT，不能借用机器人EEF或原真人腕部标签。
- **泛化或真机收益**：当前没有实测。4个视频、3个任务来源不足以检验训练增益；重复渲染也不会自动增加任务逻辑覆盖。

目前所有自动gate仍为`needs_review`，主要包含覆盖不足，不能等同于四个视频都做错了任务。白碗还暴露观察区间与末态窗口定义的不匹配：已有8秒终帧证据，但支撑关系的聚合区间从5.666667秒开始。后续需要明确“末帧状态证据”和“连续稳定支撑证据”的不同语义；不能简单删除早期证据或放宽规则来凑通过率。

## 下一步优先顺序

1. 把人物数量、对象身份/数量与可见性检查接到视频生成之前；柜门这类隐藏状态任务先补关键条件。
2. 将当前专项帧采样扩展为事件驱动的局部复核；区分任务可读、时序可靠、运动标签可信三个用途。
3. 做同预算的小规模生成对照：单首图方案与额外关键状态条件方案，统计有效配对产率、错误类型、重试成本；必须使用模型实际支持的条件接口。
4. 扩展同初态不同目标与跨布局配对，检查生成后是否仍保留目标差异，防止模型只看场景猜任务。
5. 达到任务参考准入后再接正式训练。策略效果与真机泛化属于之后的独立实验。
