# 从真实人类窗口续采仿真

本入口实现2026-10-20的要求：先落实真实人类视频里的完整原子任务，再按等价任务生成机器人轨迹。它与 `r2h_pipeline` 的合成人类视频路线分开，不需要图像／视频生成 API。

## 本次有限批次

复用已通过24条小样验收的原生专家、物理资产和192条冻结计划。之前暂停时已生成11条；先独立复核这11条，再续采从未尝试的181条：苹果换碗59、书本入开盒58、开右柜门64。192是整批计划，181是本次新增尝试预算，不是已成功数。

本批只绑定任务规格内同split的真实人类窗口：苹果3段、书本3段、柜门2段，共8段train窗口。规格里另有3段validation窗口，不借给本批train轨迹。书和柜门使用长视频里具备完整初态、操作与终态的原子片段，不能称为复现整段整理桌面／柜内取物。

苹果和书各两套已资格资产；每次独立布局重新规划，保留原资产、物体位置、背景、相机、光照随机化及原接触控制。每个小批尽量覆盖两套资产和两只活动臂。机器人本体是双Franka，但每条仍为单活动臂；柜门一个结构，沿用已验证的活动臂。真实随机化数值以每条receipt为准，没有为扩量擅自放宽已资格范围。

## 入口与数据位置

```text
/mnt/sdf/datasets/hypericl_human_robot_task_library_20261019_v1/generation/
  scale192_prepared_v1/plan.json        原冻结计划，不修改
  scale192_native_v1/                  原生新轨迹、视频、动作与接触
  scale192_bindings_v1/                每条真实人类源绑定
  resume_prior11_QC_20261020_v1/        暂停前11条的补充验收
  resume_20261020_v1/
    schedule.json                     确切181身份、任务、资源和源哈希
    state.json                        当前进度
    queues/                           每批原生执行记录
    qc/                               独立验收、阶段预览和配对候选
    summary.json                      正常完成后生成
    STOPPED.json                      发生异常则保留原因并停止
```

- `resume.py prepare` 创建不可变续采排程，排除有输出或有binding的旧身份；不会重试失败或中断身份。
- `resume.py run` 每批最多8条，三个任务轮换，只用GPU2，一次一个原生采集进程；批末自动调用CPU检查，通过后继续下一批。
- `verify_batch.py` 显式读取队列结果，避免旧watcher的硬编码路径问题；使用原生raw verifier检查成功条件、原速224/512视频、帧时间轴、全部query的EEF还原、接触、FK与源文件完整性。
- 每条 `paired_candidates.jsonl` 只列实际允许的同split人类源、精确帧窗口、初态／必要步骤／终态及允许差异。它不是按任务名自动扩充的训练参考池。

所有输出首先为待看图确认的候选；机器验收不冒充完整视觉验收。未启动模型训练、未修改旧训练清单或prepared pointer。人机对应是完整原子任务的目标与必要步骤对应，不是逐帧同步，不将人手运动当机器人motor标签。

保留150GiB磁盘余量；每批前检查GPU2实际计算进程与显存，资源被占或验证异常即停止，不影响别人的训练。每个原生调用沿用480秒上限，未知退出保留原状态，不自动再造一遍。

审计证据：[20261020审计目录](../human_to_robot_runs/20261020_v1/)。杯盖两类已找到真实完整源，但尚未验证对应仿真程序，不进入本批。

## 2026-10-20新增：规划规范与约束随机化试点

**旧实验入口已默认阻止下一批运行。** 四条物理试点之后发现旧自定义Screw planner计算了collision结果但未用于拒绝，并可能将停滞视为Success。`plan_geometry_validator.py`已对保存命令离线复跑；随后另建`strict_apple_adapter.py`实际接入live路径检查，详见下节。旧入口仍不恢复，不能继续以“已把杂物加进点云”为由扩量；原始生产源码没有被修改。

[PLANNING_GUIDE.md](PLANNING_GUIDE.md) 规定人类任务契约、相对物体规划、失败分类、位置/杂物/外观/相机分层随机化与事件条件验收。

- `planning_contract.py`：从真实冻结人类spec构建苹果任务契约，检查文件哈希和语义不变条件，给出Agent接口。
- `structured_randomization.py`：CPU候选采样与几何粗筛。当前12个v3候选，**不是12条已生成轨迹**；旧collector能力检查会明确拒绝未支持的扩展。
- `experimental_apple_adapter.py`：单独namespace实际接线更广位置、相机和静态可碰撞杂物；调用原生专家/验收器，记录额外接触，未修改冻结生产代码。必须经过小批真实执行验证，未自动扩量。
- `audit_native.py`：重新执行原生独立verifier并统计关键阶段可见性。3条旧例通过物理检查；书本抓取区间存在明显遮挡，说明要新增事件质量门。
- `verify_extra_clutter.py`：从独立读取的extra-contact sidecar重新校验时钟、力阈值和输入/资产绑定；不把静态杂物当作完整碰撞覆盖证明。

本轮确切候选与审核在 `evidence_20261020d/`。仅使用 `apple_layout_proposals_v3.json`；v1/v2为保留的开发历史，不应运行。模拟/训练准入不能由proposal或phase标签自动得出。

实际试点已有一条带2个静态可碰撞杂物的475帧轨迹通过原生物理/时间/动作检查；另一个宽布局在撤手阶段IK失败（343帧），按失败保留。详见SDG的 `real_sim_human_pipeline/sim_grounded_20261020d/`。这证明接口已真实执行，也证明粗筛不足以保证全程可达；不是批量成功率提升结论。

## 独立strict planner的后续修复

[STRICT_PLANNER.md](STRICT_PLANNER.md)记录真实实现、执行命令、接触权限、负例与资格边界。新接口使用官方mplib候选，再对时间参数化后整条路径做独立FK、终点/空间/关节/碰撞检查；每个候选保存请求、完整路径和拒绝原因。启动时自动归档本次源码，不覆盖历史输出。

严格检查确实拒绝了厘米级终点残差。将固定运输高度改为真实持物几何目标后，原layout2001失败布局在v2完成314帧并通过原生验收。之后真实mesh负例又发现安装版mplib附着物碰撞接口不足，v3进一步加入独立held-object对全部world的FCL检查、selected物体对非手部link检查，以及初始源碗支撑的窄接触许可。v3须重新跑物理资格；各版本结果不能混成一个无差别成功率。

完整table逐link检查仅豁免固定base安装接触。初始lift也开始检查payload；合法源底接触有距离、接触点高度、穿透深度和阶段限制，明细保存。所有成功仍须真实物理/时间/动作/图像审查；phase不作为接触GT，dense插值不作为连续碰撞证明，训练准入默认关闭。

本轮v3最终为15次完成尝试、14个独立配置，均通过原生物理验收；g01 clutter2重复一次须保留但不算新增多样性。它们仍只有苹果换碗1类任务。15次的105段accepted路径、4924个dense点已由CPU独立重建碰撞世界复核。原v1/v2及初始化失败分母分别保留。

新增`strict_replay_audit.py`和逐episode的模型依赖sidecar：实际运行本体使用`panda_v3.urdf`；旧source_pins里v2条目不代表实际模型。本轮依赖hash明确标事后捕获；未来入口已接运行前捕获与实际agent身份复核，不为这项元数据修正重跑仿真。原生成功依然不等于训练准入，关键事件可见性与人机语义对应还须独立确认。
