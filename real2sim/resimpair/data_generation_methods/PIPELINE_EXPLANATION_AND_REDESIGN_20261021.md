## 数据源与扩量

当前合成人类实验实际用的是 **EgoDex 的三个窗口**：苹果 2174 `[0,246)`、书本 388 `[190,261)`、柜门 1766 `[0,72)`，均 30 fps。本机统一索引共 146,033 个用途行，包含 EgoDex 141,391、HOT3D 3,832、ImItator 810；它们不等于已完成语义审核的任务。去重媒体身份 145,244，仍不是全库已解码数。

本轮检查 3,898 个唯一容器／文件定位：2,870 存在、1,028 缺失，缺失均为 HOT3D 归档；ZIP 路径存在不保证全部成员可读。实际三个输入已重新全解码。冻结任务规格有 11 个已审窗口，旧 24 条 pilot 使用其中 8 个 train 窗口；64 条逻辑配对边不能叫 64 次物理执行。Zero-WAM 的 2,499 条是独立公开清单，不是当前生成数。

可扩展，但应先复用已有机制：苹果 8006 可作为冻结后来源探针；书本 1021／799 可复用旧专家，但 strict 持物资格不能继承苹果；单杯取盖 1530 已有完整窗口规格，仍需新杯盖接触 adapter。它们均属历史已知来源，不冒称全新盲测。

具体来源、分母、全部字段及新解码帧见 [source_contract 审计](/mnt/sdg/datasets/real_sim_human_pipeline/pipeline_explained_20261021/source_contract/FACTS_ZH.txt)。

## 角色、窗口、语义与合同怎么得到

当前主要路径是“原始类别／描述／对象词检索 → 导出原速视频、PTS 和密采样图 → agent 看初态、必要步骤、释放／撤手 → 代码编译规格”。已审苹果和书本记录明确为 Codex 看图，不是用户逐例手工标注；元数据中的动词集合不能直接当有序动作。

`human_task_draft.py` 的 Gemini 盲提取真实验证过 **1 个已由外部选定的柜门窗口**：72 帧中抽 24 帧，约 30.128 秒。模型输出实体、状态关系、事件、手部角色和证据帧，本地校验 JSON／引用／时序。结果仍是 draft，必要因果顺序 unknown，未自动驱动原生产合同；不能把它画成已完成自动窗口发现。

PACT 是演示简称，实际合同有不同层次：

1. 真人任务规格：来源窗口和哈希、任务目标、初态、必要步骤、终态、禁止变化、允许差异、资产／专家入口及数据划分。
2. strict 苹果运动合同：增加明确角色、坐标单位、六个阶段的前后条件、原生能力、独立验收器绑定、证据要求和失败码。当前校验器只接受已审苹果任务。
3. 生成输入：绑定一次实际机器人执行、选定真人窗口、首／终图及角色说明；旧二维位置是视觉估计，不是追踪真值。

例如苹果角色以“初始盛苹果的碗／初始空碗”识别，屏幕左右可因相机改变；目标是同一苹果移到原空碗并稳定，不能用搬碗、倾倒或桌面取苹果替代。柜门原视频标题含“取块”，实际只选开右门原子窗口，不允许宣称完成整段取物任务。

## 资产与机制适配

本地扩充索引有 **55,536 条模型来源记录，55,535 条主模型路径存在**，跨来源未做几何去重：Objaverse 46,305、ABO 7,953、GSO 1,033、Poly Haven 模型 149、YCB 96 条中 95 条现存。另有 2,537 个 RoboCasa MJCF 定义、29 套材质和 15 个 HDRI，不混入可抓物体数。

本轮家居适配仅是其中 12 类各 1 实例 CPU 预检，8 类进入仿真作为禁止碰触的静态杂物；这批新增实例主动操作资格为 0。历史机器人库另有六任务家族、3,337 条接受记录，依各自历史物理门，不能一概算作通过最新 strict 规划器。

“仍需适配”不是指什么都没有：苹果已有有效空腔碗、碗沿净空和抓放专家；书本有入开箱专家；柜门有真实被动关节与把手接触专家。扩到新资产／机制时，须核对容腔、关节、尺度、抓持部位、惯性、可达布局及独立结果检查。整物凸包可能封死碗口；静态柜子没有可操作门；关节能动也不保证灵巧手抓稳。

更方便的方式是在现有 catalog 上增加任务能力 sidecar：`required_mechanisms`、`allowed_roles`、`cavity/joint/support/grasp`、适配版本、几何哈希及限定用途的资格证据。按“同机制已验证 → 待小样适配 → 原始检索候选”返回结果，再固定 UID／哈希交现有 loader。当前通用 index 的 `physics_qualified=false` 是收录时默认值，不应误解为撤销专用后验资格。

这是建议接口，尚未接成任意任务自动检索／加载器。详见 [资产与机位审计](/mnt/sdg/datasets/real_sim_human_pipeline/pipeline_explained_20261021/sim_assets/AUDIT.md)及 [建议协议](/mnt/sdg/datasets/real_sim_human_pipeline/pipeline_explained_20261021/sim_assets/proposed_task_asset_view_contract.json)。

## 动作、状态、相机与按需可见性

动作记录发出的指令；状态记录位姿、抓持、接触和关节；图像记录实际可见结果。共用时间轴用于提取条件图、事件定位、独立物理复查和配对，不是在视频里制造真实人手 3D 标签。物理验收主要是数值和几何程序，不靠 VLM 肯定回答。

**同意清晰桌面优先固定对面机位，额外可见性 VLM 按需启用。** 两个同步苹果布局中，对面机位闭爪阶段均 16/16 帧达到原诊断像素量；没有这两例对面机位失败的证据。目标、对象角色和必要顺序须保持，相机和人手入场位置不必复制真人视频。多视角可选，也不增加独立动作计数。

建议合同 `visibility_vlm_check=0` 用于已适配、清晰、简单桌面；拥挤遮挡、大物体密集、柜内显露、细小接触或廉价初筛异常时置 1，并明确 `reason/event_ids`。0 只省略额外可见性 VLM，物理、人物和对象身份检查仍按各自要求执行。1 表示待审核，不是通过，也不绕过预算自动提交。该调度尚未替换默认验收。

本轮另发现旧 `audit_multiview.py` 的真实抓持分支仅处理二维 grasp，实际数组是 `[frame,robot,object]` 三维。保留旧代码／报告，新增独立复算：开发例真实抓持 123 帧，原视角 91/123、对面 123/123 达到 16 像素；验证例两视角均 103/103。脚本再次复跑完全一致，见 [复算脚本](/mnt/sdg/datasets/real_sim_human_pipeline/pipeline_explained_20261021/sim_assets/recompute_grasp_visibility.py)。像素量仍不能证明指垫接触细节，未来应在独立新版本接好这条统计分支。

## 条件图与视频质量

当前接入模型的请求别名为 `gemini-3.1-pro-preview`、`gemini-nano-banana-2.1`、`doubao-seedance-2-5-260628`。它们来自实际中转请求／响应，不独立证明底层权重身份。

视频生成输入是任务文字＋人类首图，B 组增加人类终图；不是整条机器人动作、深度或逐帧 RGB 驱动的动作重建。这解释了为什么抓取细节、隐藏物体和条件间过程可能自由变化。

本轮清点全部 **14 条唯一生成视频**，均完整解码；助手看统一 16 帧及有明确引用的旧密帧证据。暂不计人物：12/14 终态目标可见，9/14 获局部任务参考支持，4 条方向／回跳／对象反例、1 条隐藏内容未知。仅三任务、三来源，多次重抽高度相关；这些不是独立留出成功率、完整接触正确率或全片无瑕疵率。受控初轮 4/6、后验 1/2、历史探索 4/6 分开记录。

十张生成锚图（5 首图＋5 终图）中，5/5 可见初态可读，4/5 可见终态符合要求；人物维度 6 张多人／三手、4 张身体归属未知。可以说外观和任务示意清楚，不能说单人首图已通过。详见 [逐视频／逐图质量和工具接线](/mnt/sdg/datasets/real_sim_human_pipeline/pipeline_explained_20261021/quality_repair/QUALITY_AND_REPAIR_EXPLAINED.md)。

## 验收与修复的实际分工

| 层次 | 工具与职责 | 不能冒称的能力 |
|---|---|---|
| 完整性 | FFprobe／Python 检查解码、帧数、PTS、哈希、来源／划分 | 文件可读不等于任务正确 |
| 仿真物理 | 对应机制的独立状态／接触／几何验收器 | 苹果资格不能传给所有新接触机制 |
| 人物／静态条件 | agent 或 VLM 给观察；规则门校验绑定和分项证据 | 规则门本身不是视觉检测模型 |
| 局部视频诊断 | OpenCV 背景配准／ROI／边界变化，MediaPipe 手部初筛，事件密帧 | 手数仅可见下界，近邻不是抓持，0 告警不是合格 |
| 语义复核 | Gemini 对证据帧输出目标／事件／身份判断，未知或矛盾时 agent 复查 | 柜门大格板曾全 yes，不能当终裁 |
| 修复调度 | 协议恢复、条件补齐、局部审查、特定生成 CLI 与预算账本 | 通用 `repair_router` 仅出计划，`actions_executed=false` |

已有实际链路包括：未知提交先查询恢复；苹果经状态差分修终图再生成；柜门专用首尾条件 dispatcher；书本接触区补十个密帧。隐藏物变大不能用同请求无限重抽，人物首图错应先修首图，抓持不稳应改资产／控制。专用 handler 已接，未实现分支停止；后处理写 `needs_generation_repair` 不会自动完成下次生成。通用分段生成、局部视频编辑仍是后续方案。

## 本轮决策与持久边界

保留六环节演示命名 CLIP / PACT / CAST / SYNC / HUM / SENTRY，用来解释现有代码职责，不声称又实现六套系统。支持固定对面＋风险标签的简化方向，保留能力检索 sidecar 方案；没有修改旧规则来提高通过率。

扩量优先同机制新来源，其次新对象／布局，再新增接触机制。记录有效配对、实际耗时／扣费和外部介入；历史费用不能从账户累计额归因。此前稳定抓持失败、资产惯性问题及单人图尚未验证仍保留。

演示验证包括 20 页、7 段嵌入视频原始 SHA、40 项媒体绑定、字体家族／字形覆盖和压缩包完整性。生产代码没改，本轮未重跑物理或全量代码回归；上一轮 778 项／18 子测试仍是其对应源码的验证记录。新证据、最终审阅和接手状态均另存，不覆盖先前 PPT。
