## 为什么修改

原 batch 16、20,000 optimizer steps 是试运行预算，不是经过验证的收敛点。它只产生 320,000 次查询位置采样；每次查询包含参考视频、当前观测及 16 步动作目标，并不等于读完整条轨迹。

旧运行在约 500 步时动作训练误差下降，但未来特征预测仍差于复制上一帧，顺序判断接近随机；不足以判断收敛。旧在线验证完全来自外部来源，无法判断 Panda 控制误差，这是比单纯延长训练更关键的问题。旧运行已停止并保留 checkpoint 500，新的正式训练从预训练 DINO + 随机可训练模块开始，不能恢复旧 checkpoint：新留出的验证轨迹曾属于旧训练集。

原五个 unseen 任务的 benchmark 训练轨迹继续排除。依照用户要求，外部数据可以包含类似或相同语义任务；因此最终指标应标明“benchmark unseen + 外部任务迁移”，不能解释为从未见过该任务语义。

清理沿用 v3 审计：数组 shape/有限值/状态范围/速度/有效掩码、源 episode 去重与采集组隔离、视频长度及分层解码抽检。验证报告核对 manifest 哈希。没有把数值有效等同于经过独立标定的高精度动作。质量层 Q0/Q1/Q2 以及各自 mask 和置信权重保留，低质量视频只参加视频辅助任务。

每个物理 batch 使用分层来源配额，使样本数接近表中比例；不足一个样本的低比例来源在不同 batch 中轮换。benchmark 内任务保持均衡。外部来源内部按任务/目标可用轨迹数的平方根加权，减轻只有 1–3 条的任务被反复过采样，同时避免大类完全占据训练。

这次只提高采样权重，不复制文件或改变训练/验证划分。原 3,000 条任务在每个有效 batch 中平均约占 38.4/64 个查询，较此前 45% 增加三分之一；同款 Panda 合计 75%。保留人类参考桥接和外部数据以继续学习迁移。人类参考视频本身也会作为 Panda 动作查询的条件被读取，其使用量不只表中的 5% 独立视频查询。

参考配对优先完整目标一致，不仅看动作动词。原 Panda 样本有 70% 概率优先同目标人类参考；其他来源支持同目标跨轨迹、跨场景或自身视频作为参考。弱匹配保持低权重且不充当精确同任务一致性正例。模型输入不含 task ID，任务标签仅用于采样与构造监督。

## 一次训练更新发生什么

1. 抽取轨迹、查询时刻与参考视频，参考视频均匀取 10 帧；当前观测和状态来自 query 轨迹，目标为未来 16 个相对动作。无动作样本保留视频任务，动作 mask 关闭。
2. 冻结 DINOv2-large 编码。参考经过 E 视频编码、T 上下文建模、R 细化、D 参数生成，产生共享 DiT policy 的动态参数。当前图像、状态、目标动作空间和 action_dt 参与条件，当前观测对事件表示做注意力选择。
3. 用有噪动作和 flow 时间训练速度场，最终生成相对末端动作。机器人每臂 `[dx,dy,dz,rotvec_x,rotvec_y,rotvec_z,openness]`，双臂 14 维；单臂第二槽屏蔽。全部目标相对同一个查询时刻末端坐标系，不逐步积分。各工具参考点、状态及归一化仍由独立适配器区分；人类手腕有独立 20 维空间。
4. 同时训练过去上下文预测未来 DINO 特征、时间顺序、任务对比和双参考行为一致性。未来分支只读取过去上下文；参考分支允许整段示范，这符合部署时先提供完整示范的用法。
5. 两个物理 batch 的梯度累积后做一次 AdamW 更新。动作 loss 通过 policy 与生成参数回传 D/E/T/R；一致性 loss 也经过 D。未来预测主要训练 E/T/R 与未来头，不直接监督 D。没有专家任务 LoRA 参数拟合/参数蒸馏阶段。

|损失|权重|额外说明|
|---|---:|---|
|动作 flow matching|1.0|真实 Franka/AgiBot 置信权重 0.5；人类运动 0.35|
|未来 DINO 特征|0.05|另记复制上一帧误差及两者差值|
|时间顺序|0.02|识别视频顺序|
|任务对比|0.02|同完整目标参考作正例|
|双参考速度场一致性|0.02|只约束可信同目标配对|

RGB 像素预测权重为 0，当前并不是高清未来帧生成训练。辅助项在前 2,000 次更新逐渐加到全权重，日志 `optimized_loss` 记录实际加权优化目标。总参数 339,379,074；可训练 34,033,693，其中 E/T/R/D 18,434,959、policy target 14,164,000。

## Batch、步数与吞吐

正式配置 GPU 1，物理 batch 32，累积 2，有效 batch **64**，BF16。GPU 1 是卡编号，此进程使用一张卡。保留 lr=1e-4，warmup 500，梯度裁剪 1，cosine 到 100,000 步并保留 0.1 倍最低比例。

100,000 是新的可执行上限，不代表预先知道此时会收敛。最多 6,400,000 次 query 采样，是旧 20,000×16 的 **20 倍**。原任务与外部来源按权重重复采样，不能把此数直接除以轨迹数称作精确 epoch。

依照用户要求，统一使用名义 epoch 标尺：`ceil(18804 / 64) = 294` 次 optimizer update；每轮相当于 18,816 次查询抽样，不是保证遍历所有轨迹或帧。日志保留 step，并增加小数 epoch、已完成 epoch、累计 query 数。`epochs.jsonl` 汇总每个 epoch 内所有更新的平均损失、各来源实际数量与比例；从旧 checkpoint 在 epoch 中途接入的第一段标记 `partial_epoch=true`。总预算相当于约 340.14 个这样的 epoch。

梯度累积扩大动作监督的有效 batch，但不会把任务对比损失的负例池自动扩大到 64 个 query：每个微 batch 仍只有 32 个 query、最多 64 个参考视图，实际还受来源和目标掩码影响。64 不是实验确定的最优值，先看与旧试运行相比的稳定性和验证结果。

GPU smoke 实测峰值分配约 4.42 GiB；设置 PyTorch 显存上限 18%，用于与当前其他任务共用 GPU。固定 10 帧参考使用冻结 DINO 特征的惰性缓存，预计完整约 13 GB，目录 `/mnt/sdf/datasets/hypericlzq_reference_cache/dinov2_l_224_f10_p32`。当前帧、随机上下文和未来帧继续动态编码；不因参考缓存失去查询时刻变化。验证 token 单独固定缓存，减少重复视频解码。

总训练计算量明显增大，原约 20 小时估计失效。冷缓存小试的每步约 11–17 秒，若长期如此，100,000 步约 13–20 天；这仅是未充分缓存时的外推，实际受参考命中率、数据 I/O 和共用 GPU 负载影响，需要按正式日志的区间速度更新。不得把更大预算说成免费加速或收敛保证。

## 验证与停止/继续判断

每 1 个名义 epoch 保存滚动恢复点后做离线动作验证，使用固定种子、固定 clip/noise 的 16×16=256 个混合样本面板；这是低成本趋势监控，不是遍历全部 1,263 条验证轨迹。验证记录各动作空间独立、未加来源置信权重的 flow error，避免总 loss 被来源比例掩盖。它与仿真任务成功率评估不同。

Panda 进一步真实采样动作，计算毫米位置误差、SO(3) 旋转角误差和夹爪准确率；另记目标确实运动的子集（位移 >5 mm 或旋转 >0.035 rad）。比较三种情况：正确参考、不同任务参考、保持当前末端与夹爪不动。正确/错误参考采用相同初始噪声。`best_panda.pt` 按运动子集的位置误差选择，并同时保存其他指标；它仍然不是按任务成功率选出的最优模型。

看连续多个检查点的趋势：

- Panda 验证误差能否优于不动基线，原任务闭环成功率能否提高。
- 正确参考是否优于错误参考；若两者长期无差别，检查模型是否忽略示范。
- 未来预测能否优于复制上一帧；否则不把该辅助项称为有效学习。
- 训练下降而验证上升时，检查重复采样、配对和来源权重；不能只追加步数。
- 多次验证进入平台后仍须结合闭环成功率决定停止、减学习率或继续。当前不启用按一次验证波动自动早停。

每 **5 个名义 epoch（1,470 次更新）**保留独立 checkpoint：`epoch_0005.pt` 对应第 1,470 步，`epoch_0010.pt` 对应第 2,940 步，以此类推。`checkpoints.jsonl` 记录索引，写完临时文件后原子发布，拒绝覆盖已有同名保留点。`last.pt` 仍在每轮离线验证前、恢复后的第一步和结束时滚动更新，防止异常退出丢失太多进度；它不占用新的历史文件。训练上限内共 68 个五轮保留点，按目前约 394 MiB/份，合计约 26.2 GiB，另有 last/best/修订备份。

原 seen、seen-heldout、unseen 的 L0–L3 闭环指标继续是最终标准；unseen 不用来筛选在线 checkpoint。相对动作经 FK 还原目标、IK 到原控制器执行，记录 IK 失败率。不同来源 FPS 和 TCP 仍不同，action_dt 与适配器缓解差异，但不能声称已经完全统一物理控制问题。

### 评估时固定生成参数

参考视频的 E/T/R 编码在每个 episode 开始时计算一次。原评估只缓存了该编码，D 仍会随当前观测每步重新解码，生成的策略参数可能频繁变化。现在缓存的是 **D 的完整输出参数 P**：默认在控制步 0、32、64、96……更新，其间复用完全相同的参数张量。

`--hyper-update-interval 32` 表示保持 32 个环境控制步；`0` 表示整段 episode 只生成一次；`1` 仅用于复现旧版逐步生成的对照实验。500 步的 episode 默认只调用 D 16 次，而不是 500 次。每个 episode 重置缓存，避免继承上一任务的参数。

固定 P 期间，policy 仍每步读取当前画面、状态并预测动作，保留原时间聚合平滑。相对末端动作仍按当前查询状态转换；不会复用旧状态或旧动作坐标原点。动作查询频率与 hypernet 参数更新频率是两个不同设置，本次只降低后者。评估不执行梯度更新。

每个环境结果记录 `hyper_update_interval`、`policy_queries`、`hyper_parameter_updates`、`hyper_update_steps_by_episode`，可以直接核对实际更新时刻。新结果在 `eval_epoch_0030_hyper32`，旧的 `eval_epoch_0030` 标记 superseded，不能混合汇总成功率。训练 forward 和正在运行的训练进程不受这一评估修改影响。

资源允许时可以如下运行一个完整套件：

```bash
CUDA_VISIBLE_DEVICES=3 HF_HUB_OFFLINE=1 USE_TF=0 OMP_NUM_THREADS=4 \
VK_ICD_FILENAMES=/etc/vulkan/icd.d/nvidia_icd.json \
.venv/bin/python -m examples.baselines.hypericlzq.evaluate \
  --checkpoint /mnt/sdf/datasets/hypericlzq_runs/eef_v31_20260925/epoch_0030.pt \
  --output /mnt/sdf/datasets/hypericlzq_runs/eef_v31_20260925/eval_epoch_0030_hyper32/seen_heldout \
  --suite seen_heldout --num-episodes 10 --max-steps 500 --hyper-update-interval 32
```

GPU 编号应依据执行时空余资源选择；更换 checkpoint 或参数更新间隔时使用独立输出目录。

`evaluate.py --suite seen_heldout/seen/unseen` 支持完整评估；`--reference-mode wrong_task/blank` 用于参考消融。3 步小试只检查接口可运行，不能报告为任务成功率实验。完整评估需使用足够 rollout 长度和种子，之后才可判断扩充数据是否提高 seen/unseen 成功率。
