## 检查如何取舍

| 检查 | 后续约定 |
| --- | --- |
| 动作有效、关节顺序、坐标系、起点、共同时间轴、关节限位 | 保留硬检查。修复输入或执行契约后才能继续。 |
| 双臂、持物与环境的禁止碰撞 | 保留检查；正常抓取、支撑、放置接触按任务阶段定义许可。代理几何重叠先作疑似，能精细复核时用实际碰撞形状复核。尚不能排除时可暂停规划，但不能报告为已发生物理碰撞。 |
| 实际抓住、失抓、掉落、实际释放、持物模型有效性 | 保留监测。失效后进入合法恢复或终止，不能继续使用物体仍在手上的假设。不得仅放宽滑移数字而沿用已失效的附着几何。 |
| 官方任务成功与时限 | 依据环境独立报告。本轮三个任务保留官方200步时限；旧400步能力实验不能混作官方通过。 |
| 连续5步抓稳、5毫米位置滑移及类似固定数值 | 改为版本化的任务配置，保留确认抓稳与滑移监测。区分质量偏差和持物模型已失效，不能用同一数字代替两者判断。 |
| 退手8厘米、最终稳定20步 | 改为可选质量要求，按任务选择距离、观察时长及接受规则。仍须确认任务要求的真实释放和放置结果。 |
| 提前要求至少3步收敛余量 | 取消统一硬拒绝。预算用于实际调度、缩短冗余阶段或重规划；余量不足属于调度/预算事件，不能标成物理失败。真实时限仍生效，不能超时后继续完成再计通过。 |
| 全量GPU读回、重复源码哈希、详尽逐子步归档 | 完整审计主要用于验收和诊断。常规生成仍做必要的实时物理监测，保存轻量证据；减少归档不能等同于关闭碰撞或失抓检测。 |

代理几何应修正表示或增加适用的精细复核。仅凭外包框或碰撞球重叠，不能断言实际实体已经碰撞；实际禁止接触也不能因代理几何有误而忽略。

## 新增检查与运行记录

- 除执行契约和明确的物理失效外，新增检查先记录观测及原因，检查误报，再决定是否成为特定任务的接受条件。不要每遇到一次失败就增加一个全局距离、角度或等待步数。
- 每个任务选择并保存自己的质量配置，注明单位、控制频率与版本。执行、回放、汇总读取同一份冻结配置，不能分别硬编码不同数字；配置未选用或未观测的质量项报告“未评估”。
- 常规生成保留动作、初态、任务/种子、生成器和后端版本、配置、必要目标状态及碰撞/失抓/释放/超时等事件。版本身份可在批次开始记录并由轨迹引用；有未提交源码时保存其差异身份。
- 验收/诊断模式再启用完整读回、详细物理子步和较重的身份审计。正常模式也必须具备完成所选实时检查需要的观测，不能依靠事后日志代替运行监测。
- 常规动作回放重点核对机器人、目标物体、原动作执行和任务结果。背景物体的逐帧严格一致性作为专项确定性测试；背景物体若实际影响碰撞或任务，仍要纳入相应物理检查。

## 结果分别报告

以下是报告内容约定；阶段 1 新报告已新增 `results` 分层，具体字段见[收敛快照](INFRA-CONVERGENCE.md)，其余迁移按阶段验收：

1. **官方结果**：官方成功条件、是否超时、实际环境步数。
2. **执行与物理结果**：执行契约是否有效，是否检出禁止接触、失抓、掉落、未释放或失效持物表示，以及是否恢复。
3. **质量结果**：所选配置及版本、各指标实测值、通过/未通过/未评估。官方成功但可选退手指标不足，应同时保留这两个事实。
4. **过程事件与数据完整性**：规划拒绝、精细复核、预算调度、重规划、录制或回放问题分别记录，不合并为“物理失败”。

新约定不追溯修改旧评分。旧轨迹仍可按其原质量配置使用；需要新口径时另存派生评估，并保留原报告与源码身份。未通过可选质量项的轨迹可分层筛选，实际失效与损坏记录不能混入合格数据。
