# 把 AI 内置进平台：可行性与实现（v0，2026-11-12）

## 1. 判断

可行，而且值得做，但要守住一条原则：**AI 负责提出，物理验证负责裁决。**

这个平台的核心价值是“判定可信”。如果 AI 的输出没有经过检验就成为结论，平台就会自己制造出它要解决的那类问题：可以被钻空子、无法复现的判据。所以 AI 在平台里有三个位置：

1. **加速器**：起草任务合同、审查判据、提出反例、解释失败原因。产出都只是**候选**，必须经过确定性检验（执行仿真、跑反例、跨引擎）才能入库。
2. **被测对象**：VLM 裁判、奖励模型、世界模型、coding agent。平台用自己的物理真值去度量它们的可信度。本轮的 E2 就是第一次这样做。
3. **使用者**：外部 agent（Claude Code、Codex 等）通过工具接口调用平台，跑仿真、测物理量、做审计、出渲染图。评测时使用隐藏判据，防止它们学会讨好判据（对应 2611.08318 的“判据暴露”问题）。

## 2. 嵌入点（按用户的工作步骤）

| 步骤 | AI 做什么 | 怎样检验 | 成熟度 |
|---|---|---|---|
| 写任务 | 根据指令或人类视频描述，起草任务合同（结果项、阈值、反例） | 先校验结构，再要求专家必须通过、反例必须失败、跨引擎给出相同结论 | 中高：LLM 擅长结构化起草，但阈值必须用数据校准 |
| 审判据 | 读 `evaluate()` 源码和任务指令，指出语义缺口，并给出可执行的反例 | 和静态检查交叉核对；只有当反例在仿真中**真的骗过了判据**，才算确认 | 高：读代码是 LLM 的强项；原型见 `ai/loop.py` |
| 红队反例 | 针对一个判据，提出“不完成任务也能通过”的行为，用路点或技能 DSL 表达 | 由仿真执行，只保留真正暴露缺口的行为 | 中：需要能执行行为的 DSL 和多轮迭代 |
| 搭场景、接资产 | 从视频或扫描构建场景，检查资产尺度和类别是否合理 | 跨引擎检验，和视频比对，再用 ReSimPair 式的验收器 | 中低：Video2World 和 Agentic Real2Sim 说明这件事可行但很难 |
| 解释失败 | 读特权状态轨迹，回答“为什么失败”，并给出证据（时刻、物理量） | 证据必须能在记录里查到对应的数值 | 中高 |
| 判定难以测量的结果 | 用 VLM 判断“擦干净了吗”“摆得整齐吗”这类没法直接测的结果 | 先在有物理真值的近失败样本上测它的可信度（E2），带着可信度分数使用 | 取决于 E2 的结果 |
| 分析结果 | 用自然语言查询排行榜和评测记录 | 答案附上查询语句和原始数据 | 高 |

## 3. 实现架构

```
veritask/ai/models.py   统一模型接口：LocalVLM（本地 GPU，数据不出机器、无单次调用费用）
                        和 OpenAICompatible（vLLM 或商用 API；密钥只从环境变量读取）
                        每次调用都记录：模型名、提示词哈希、输入、输出、耗时（CallRecord，jsonl）
veritask/ai/loop.py     review_predicate / draft_contract / propose_counterexamples：只产出候选
veritask/audit/*        确定性检验：静态检查、反例运行、可信度指标、跨引擎一致性
veritask/judges/*       把 AI 当被测对象：在有物理真值的样本上度量它
（计划）tools/mcp_server   把 run_episode / measure / audit / render 暴露给外部 agent；评测时使用隐藏判据
```

**从 ReSimPair 借鉴的工程经验**：

- 每次调用都写入账本；设定并发上限和超时；如果调用结果未知，先恢复查询，不要重新提交。
- 缓存按“提示词哈希 + 模型版本”做键。
- AI 产物和原始输入一起冻结，保证可以复现。

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| 模型虚构判据缺口 | 只有反例在仿真中真的成功骗过判据，才算确认 |
| 结果不确定，模型版本会漂移 | 固定模型版本、温度设为 0、缓存输出；模型产物只作为候选，最终由确定性检验决定 |
| 成本 | 默认使用本地开源模型（E2 实测本地 8B VLM 的单样本耗时，见结果文件）；商用 API 只在明确授权后使用，并记入账本 |
| 提示注入和安全（ArmedAgent 显示数字世界的攻击能穿透到物理世界） | 任务文件和视频只当数据处理；agent 生成的代码只在沙箱内运行；涉及真机的调用需要人工确认 |
| 被测 AI 过拟合判据 | 判据分成公开的训练集和隐藏的测试集，测试集定期轮换 |

## 4.5 已实现的接口（2026-11-12）

- `ai/backends.make(name)`，可选的后端：
  - `local`：本地 VLM；
  - `openai`：OpenAI 兼容接口；
  - `claude`：`ai/claude_backend.py`，使用官方 Anthropic SDK。默认模型 claude-opus-5-5，`fallbacks: "default"`（遇到拒答时由服务端自动换模型），effort 可配置。**尚未连真实 API 测试**；
  - `agent`：`ai/agent_queue.py`，由会话中的 agent 代答，是接入商用 API 之前的替代；
  - `gemini`：只预留了名字。
- `judges/calibrate.py`：
  - PlattCalibrator：用仿真标签校准裁判输出的分数；
  - export_sft_jsonl：把近失败样本导出成训练数据；
  - FineTuneJob：只有接口，没有实现。

## 5. 路线

- **v0（本轮）**：模型接口、调用账本、裁判评测（E2）、判据审查原型。
- **v1**：根据 Imitator 任务描述起草任务合同；用已确认的缺口作为标注，度量判据审查的召回率和精确率。
- **v2**：红队反例的行为 DSL 和执行器；对外的工具接口（MCP），以及隐藏判据评测。
- **v3**：agent 从人类视频构建任务，接入 ReSimPair 的任务合同，并做自动验证。
